# 제어 어댑터 계약

Benny는 모든 앱을 시작하고 조작하는 법을 알지 못한다. 사용자는 대상 앱에 맞춰 이 계약을 구현하는 control 스킬이나 어댑터를 하나 설정해야 한다.

그 스킬 이름은 `control.skill_name`에 넣는다.

완성한 사용자 관점 기능 맵(feature map) 경로는 `control.feature_map_path`에 넣는다. [`feature-map.example.md`](./feature-map.example.md)를 `.cursor/automations/benny/` 밖으로 복사해 채우고, 복사해 온 예시 자체는 편집하지 않는다.

스킬, 기능 맵, 필요한 기능 중 하나라도 없거나, 모호하거나, 불완전하면 재현과 수정 작업은 닫힌 쪽으로 실패(fail closed)해야 한다.

## 필수 기능

### 띄우기(Bring up)

요청된 앱 리비전을 요청된 테스트 환경에서 시작한다.

입력:

- 저장소와 리비전
- 빌드 또는 시작 모드
- 워크스페이스, 계정, fixture, 기능 상태 요구사항
- 산출물 디렉터리
- 완성된 기능 맵 경로

반환:

- 세션 식별자
- 어댑터가 올바른 앱과 환경임을 어떻게 확인했는지
- 안정적인 앱 마커
- 이후 호출에 필요한 실행 중 프로세스나 대상 세부 정보
- 빠진 기능

어댑터는 대상 앱을 비슷한 창, 셸, 프로덕션 인스턴스와 구별해야 한다.

### UI 조작(Drive UI)

실제 사용자 동작을 수행한다.

- 클릭
- 타이핑
- 키 누르기
- 스크롤
- 드래그
- 크기 조절
- 앱 컨트롤을 통한 이동

role, 라벨, 안정적인 선택자를 우선한다. 좌표는 새 스크린샷을 찍은 뒤에만 쓴다.

동작마다 그 동작과 관찰된 상태 변화를 반환한다.

증상을 만들려고 내부 상태를 설정하거나, 숨은 앱 메서드를 호출하거나, 저장소에 직접 쓰거나, DOM 변경을 주입하지 않는다.

### 맵에 있는 기능과 상태 조작

앱을 조작하기 전에 기능 맵의 관련 절을 읽는다.

어댑터는 다음 방법을 제공해야 한다.

- 맵에 있는 모든 기능을 사용자에게 보이는 경로로 탐색한다.
- 그 기능에 나열된 어댑터 동작 이름을 호출한다.
- 해당하는 경우 default, hover, focus-visible, active, disabled, loading, empty, error, selected, open, expanded, 기능별 상태와 상호작용한다.
- 안전한 fixture 데이터, 권한, 플래그, 서비스 응답, 지원되는 테스트 컨트롤로 상태를 준비한다.
- 두 번째 독립 재현 시도를 위해 기능을 초기화한다.
- 기능 맵이 지정한 스크린샷, 동영상, 읽기 전용 교차 확인을 캡처한다.

role, 접근 가능한 이름, ARIA 관계, 안정적인 컴포넌트 마커, 목적에 맞게 이름 붙인 data 속성을 쓴다. 생성된 CSS나 StyleX 클래스, 동적 해시, 자식 인덱스, 깨지기 쉬운 DOM 위치는 절대 쓰지 않는다.

전제 조건을 준비하는 것이 보고된 증상을 주입해도 된다는 허락은 아니다. 재현 자체는 여전히 실제 사용자 상호작용에서 나와야 한다.

### 상태 검사(Inspect state)

UI가 보여 주는 것을 확인하려고 상태를 읽는다.

예:

- 접근성 트리
- DOM이나 뷰 계층
- 프로세스 상태
- 로컬 로그
- 네트워크 요청 상태
- 앱이 노출하는 디버그 상태

검사는 읽기 전용이다. 조회가 상태를 바꾼다면 그것은 `drive UI`에 속하고, 실제 사용자 동작을 나타내야 한다.

### 스크린샷(Screenshot)

현재 앱 상태를 요청된 경로에 캡처한다.

반환:

- 파일 경로
- 캡처 시각
- 앱 마커나 창 제목
- 보여야 할 내용에 대한 짧은 설명

스크린샷에는 올바른 앱을 테스트 중임을 증명할 만큼 앱의 크롬(chrome)이 보여야 한다.

### 녹화(Recording)

전체 재현 경로를 감싸도록 화면 녹화를 시작하고 멈춘다.

반환:

- 파일 경로
- 시작 시각과 종료 시각
- 캡처한 창이나 영역
- 오디오나 민감한 오버레이를 뺐는지 여부

녹화에는 준비 과정이나 로딩 화면만이 아니라, 결함을 판별하는 최종 상태가 보여야 한다.

### 정리(Cleanup)

어댑터가 만든 프로세스와 세션을 멈춘다.

일회용인 다음 것을 지운다.

- 브라우저나 앱 프로필
- 임시 워크스페이스
- 어댑터가 만든 테스트 계정이나 fixture
- 디버그 포트와 터널
- 보존 기간이 지난 캡처

무엇을 멈췄고, 지웠고, 남겼고, 사람에게 맡겼는지 반환한다.

정리는 사용자의 작업을 지워서는 안 된다.

## 어댑터 동작

어댑터는 다음을 지켜야 한다.

- 재현을 시작하기 전에 기능을 보고한다.
- 기능 맵의 어느 절을 조작할 수 있고 어느 절이 막혔는지 보고한다.
- 기준 빌드와 패치 빌드에 같은 환경 입력을 쓴다.
- 시작 실패는 실패로 드러낸다.
- 재시도 횟수에 상한을 둔다.
- 비밀 정보가 로그와 산출물에 들어가지 않게 한다.
- 캡처는 저장소 밖에 둔다.
- 두 재현 시도 사이에 새 상태나 초기화된 상태를 지원한다.
- 사용자가 안전한 테스트 동작을 명시적으로 설정하지 않았다면 프로덕션을 바꾸지 않는다.

## 환경 번역

환경 때문에 막혔다고 선언하기 전에, 플랫폼 고유 명사를 빼고 결함을 다시 서술한 뒤, 같은 동작을 쓸 수 있는 환경에서 안전하게 테스트할 수 있는지 묻는다.

예:

- 특정 브라우저 이름은 아무 외부 브라우저를 뜻할 수 있다.
- 특정 키 이름은 설정된 단축키를 뜻할 수 있다.
- 특정 원격 호스트 이름은 지연되거나 끊긴 원격 대상을 뜻할 수 있다.

번역한 시도는 같은 근본 동작을 테스트할 때만 쓴다. 번역된 증거라고 라벨을 붙인다. 빠진 환경 자체가 결함의 일부라면 정확한 재현이라고 부르지 않는다.

하드웨어 프롬프트, 운영체제 권한 대화상자, 기기 전용 API, 사용할 수 없는 계정 상태는 진짜 막힘일 수 있다.

## 설정 확인

재현 자동화를 켜기 전에 무해한 어댑터 확인을 한 번 돌린다.

1. 앱을 띄운다.
2. 안정적인 앱 마커를 확인한다.
3. 완성된 기능 맵 절 하나를 불러온다.
4. 그 기능으로 사용자 경로를 따라 이동한다.
5. 맵에 있는 어댑터 동작으로 일회용 상태 하나를 다뤄 본다.
6. 그 결과 상태를 검사한다.
7. 스크린샷을 찍는다.
8. 짧은 클립을 녹화한다.
9. 정리한다.

아홉 단계가 모두 성공하고 원본 채널 Slack 게시가 끼어 있지 않을 때만 재현 작업을 켠다.
