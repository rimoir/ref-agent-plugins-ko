# Ketchup

`/ketchup` 전에 사용자가 쓴 마지막 메시지 이후 이 채팅에서 일어난 모든 것을 따라잡게 한다. 알림과 subagent 결과는 사용자의 메시지가 아니다. [`/bro`](../bro/SKILL.md)의 쉬운 말투로 쓰되, 다시 말하기 단계는 건너뛴다. 사용자는 자기 마지막 메시지만 기억하고 그 뒤로는 아무것도 모른다고 가정한다. PR, 브랜치, 에이전트는 작업 중에 지어낸 라벨이 아니라 사용자가 알 만한 이름으로 부른다.

## 바뀐 것 모으기

이번 턴은 읽기 전용으로 둔다. 예외는 이미 가진 것으로 응답용 시각 자료를 만드는 일뿐이다. 시각 자료를 만들려고 코드를 바꾸거나, 앱이나 작업을 시작하거나, 무언가를 올리지 않는다. 그 메시지 이후 내가 한 작업, subagent의 보고, 이 채팅의 다른 사람이 보낸 메시지를 모은다. 이 채팅이 건드린 PR, CI 실행, 에이전트마다 현재 상태를 확인한다. 무엇이 아직 돌고 있고 무엇을 확인하지 못했는지 말한다.

실행 항목은 사용자만 내릴 수 있는 결정이나 단계다. 제품 선택, 승인, 되돌릴 수 없는 행동, 내게 없는 접근 권한 같은 것이다. 사용자의 마지막 메시지 전에 나온 것이라도 아직 사용자를 기다리고 있으면 넣는다. 내가 아직 직접 할 수 있는 일은 실행 항목이 아니다.

## 응답 쓰기

실행 항목이 몇 개인지, 또는 없다는 것을 한 문장으로 먼저 말한다. 아무 일도 없었고 사용자를 기다리는 것도 없으면 그렇게 말하고 끝낸다.

그다음 무슨 일이 있었는지 중요한 것부터 말한다. 결과마다 그것이 사용자에게 무슨 뜻인지 적는다. 아무것도 바꾸지 않은 단계는 건너뛴다. 내가 직접 할 수 있는 남은 일은 한 줄로 적는다.

그다음 실행 항목마다 짧은 요약을 단다. 내릴 결정, 그것이 지금 중요한 이유, 선택지와 각각의 비용, 내 추천, 사용자가 답하지 않으면 생기는 일을 다룬다. 모르는 부분은 추측하지 말고 모른다고 말한다. 세부 내용이 있으면 링크하고, 사용자가 링크를 열지 않고도 결정할 수 있게 요약을 쓴다.

실행 항목마다 전후를 나란히 보여 준다. 선택이라면 선택지마다 현재 상태를 옆에 두고, 현재 상태가 없으면 선택지만 둔다. 변화가 눈에 보이면 스크린숏이나 영상을 쓴다. 그렇지 않으면 숫자 표, diff, 다이어그램 같은 다른 산출물을 쓴다. 시각 자료가 아직 없으면 만든다. 만들 수 없으면 없다고 분명히 말한다. 숫자를 지어내지 않고, 직접 캡처하지 않은 화면을 그리거나 생성하지 않는다. 실제로 있는 산출물만 링크한다.

빽빽한 산문보다 시각 자료를 쓴다. 표, Mermaid 다이어그램, 차트, 생성한 이미지를 쓴다.
