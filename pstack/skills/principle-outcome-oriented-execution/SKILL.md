# 결과 지향 실행

매끄러운 중간 상태를 보존하기보다 의도한, 검증 가능한 최종 상태에 맞춰 최적화한다.

**이유:** 모든 중간 단계를 완전히 안정적으로 유지하려 하면 임시 호환 코드가 생기고, 그것이 오래 남는 부채가 되기 쉽다. 목표 아키텍처로 수렴하고, 명시한 검증 경계에서 정확성을 증명한다.

**핵심 규칙:**
- 과도기의 안정성보다 최종 상태의 무결성을 우선한다
- 계획되고, 범위가 정해지고, 되돌릴 수 있는 중간 파손은 받아들일 수 있다

**안전장치:**
- 단계 경계가 명시된 계획적 재작성과 마이그레이션에 쓴다
- 임시 파손을 어디까지 받아들일지 선언한다
- 마이그레이션하는 동안 활발히 건드리는 영역에는 신호가 강한 검사를 유지한다
- 계획이 끝나면 정적 검증과 런타임 검증을 모두 요구한다
