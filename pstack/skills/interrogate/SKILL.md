# Interrogate

적대자들이 변경이나 설계를 깨뜨리려 한다. 지적은 실행으로 증명될 때만 남는다. 지적을 보고한다. 수정은 적용하지 않는다.

## 틀 잡기

범위는 사용자가 지정한 것이다. 지정이 없으면 base 브랜치와의 merge base부터 작업 트리까지의 브랜치 diff다. 사용자 메시지, 커밋, PR 설명에서 의도를 끌어내 **in-your-own-words** 스킬로 밝힌다. 의도가 불분명하면 사용자에게 묻는다.

## 펼치기

**arena** 스킬의 Phase A 3단계와 4단계, Phase B를 돌리되 네 가지를 바꾼다. `arena runners` 대신 `interrogate reviewers` 줄을 읽는다. 범위의 커밋하지 않은 변경을 각 worktree에 복사한다. 각 적대자는 `generalPurpose`로 띄운다. arena 과제와 근거 대신 범위, 의도, 아래 브리프를 각 적대자에게 준다.

> 이 변경을 깨뜨려라. 각 지적은 실제 코드에 대한 실행으로 증명한다. 실패하는 테스트, 재현 스크립트, 잘못된 동작을 보여 주는 명령 출력 같은 것이다. 설계나 계획이라면 프로토타입을 돌리거나 현재 트리를 탐색한다. 재현은 네 worktree 안에 둔다. 각 지적은 제목, 정확한 명령, 그 명령이 출력한 내용, 의도가 요구하는 출력과 함께 보고한다. 돌려 보지 않은 것은 빼라. 스타일, 이름 짓기, 구조, 미래의 변경이 있어야 문제가 되는 위험이 여기에 든다. 지적이 없는 것도 유효한 결과다.

## 검증

arena Phase F에 따라 각 지적의 명령을 다시 돌려 검증한다. 출력이 실패를 보여 주고 그 실패가 의도를 깨뜨릴 때 지적을 남긴다. 나머지는 버린다. 근본 원인이 같은 지적은 합친다.

arena Phase C, D, E는 건너뛴다. 적대자마다 찾는 실패가 다르므로, 판정은 적대자 하나의 목록이 아니라 검증된 지적 전부를 남긴다.

## 출력

- **Intent**: 다시 밝힌 의도.
- **Findings**: 검증된 지적마다 명령, 그 출력, 의도를 어떻게 깨뜨리는지, 그것을 찾은 적대자. 남은 것이 없으면 "검증된 지적 없음"이라고 쓴다.
- **Dropped**: 적대자마다 버린 지적 수와 그 이유.
