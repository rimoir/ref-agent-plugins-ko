# 기여하기

모든 이슈는 [`SCOPE.md`](./SCOPE.md)의 기준으로 판단한다. 먼저 읽는다.

## 요청마다 가는 곳

| 가진 것 | 가는 곳 |
| --- | --- |
| 스킬의 버그 | [Bug issue](https://github.com/mattpocock/skills/issues/new?template=bug.yml) |
| 기존 스킬의 변경 | [Idea or feedback issue](https://github.com/mattpocock/skills/issues/new?template=idea.yml) |
| 질문, 또는 "어떻게 하나요?" | [Discussions: Q&A](https://github.com/mattpocock/skills/discussions/categories/q-a) |
| 새 스킬 아이디어, 또는 기증하려는 스킬 | [Discussions: Ideas](https://github.com/mattpocock/skills/discussions/categories/ideas) |
| 다른 하네스나 이슈 트래커 지원 | [`.out-of-scope/`](./.out-of-scope)를 읽은 뒤 [Discussions: Ideas](https://github.com/mattpocock/skills/discussions/categories/ideas) |

풀 리퀘스트는 협업자만 열 수 있다. 수정 내용은 이슈에 설명한다.

## AI로 쓴 이슈

에이전트의 도움은 환영한다. 하지만 이슈를 올리는 사람은 당신이니 책임도 당신에게 있다.

- **이슈 하나에 문제 하나.** 한 세션에서 나온 발견이 여럿이면 이슈도 여럿이거나, 아예 없어야 한다.
- **짧게.** 한 화면에 들어가지 않으면 줄인다.
- **재현 먼저.** 문제를 보여 주는 단계를 분석보다 먼저 쓴다.
- **스펙을 붙여 넣지 않는다.** 완성된 제안, 계획, 다시 쓴 `SKILL.md` 파일을 붙이지 않는다. 문제를 설명한다. 수정 설계는 우리가 한다.
- **당신 프로젝트의 이슈가 아니다.** 에이전트가 당신 프로젝트의 스펙이나 티켓을 여기 올린다면 저장소를 잘못 잡은 것이다. 당신 프로젝트에서 `/setup-matt-pocock-skills`를 실행한다.
