# 기술 글쓰기

지친 엔지니어가 한 번 읽고 이해하게 쓴다.

- 일하지 않는 단어는 모두 지운다.
- 짧고 일상적인 단어를 쓴다. "utilize"가 아니라 "use"다.
- 규칙이 문장을 더 나쁘게 만들면 다른 방법으로 고치거나 그대로 둔다.
- 동의어나 설명 말고 실제 심볼, 파일, 플래그, 명령 이름을 쓴다.
- 전문어(jargon)를 지어내지 않는다. 개발자가 소리 내어 말할 법한 단어를 쓴다. 이름 붙은 패턴은 처음 나올 때 뜻을 밝힌다.

## 리듬에 변화를 준다

- 문장 길이를 섞는다. 생각 두 개를 실은 문장은 나눈다. 생각 하나를 실은 긴 문장은 그대로 둔다.
- 설명(explanation)에서는 관점을 가진다. 레퍼런스는 건조하게 둔다.
- 구체적으로 쓴다. "schema changes can cause issues"가 아니라 "a column rename fails the build"처럼 쓴다.

## 모드부터 고른다 (Diátaxis)

문서 하나에 모드 하나다. 모드를 섞지 않는다. 대신 나누고 링크한다.

- **튜토리얼: 해 보며 배운다.** 학습자가 무엇을 만들지 말한다. 모든 단계가 눈에 보이는 결과를 내고, 무엇이 보여야 하는지 알려 준다. 설명은 한 구절과 링크 하나로 줄인다.
- **하우투: 목표까지 가는 단계.** 독자의 문제를 푼다. 독자의 역량을 전제한다. 행동만 쓴다. 분기는 허용한다. 가이드 이름은 작업으로 짓는다.
- **레퍼런스: 찾아보는 사실.** 기술만 한다. 건조하고 완전하고 확신 있게 쓴다. 기술하는 대상의 구조를 그대로 따른다.
- **설명: 이해와 이유.** 경계가 분명한 주제 하나를 다룬다. 맥락을 준다. 설계 결정, 역사, 제약, 대안이다. 의견은 여기서만, 다른 곳에서는 허용하지 않는다.

## 독자에게 말하는 문장을 쓴다 (Google 개발자 스타일)

- 독자를 "you"로 부르고 현재 시제로 쓴다.
- 누가 무엇을 하는지 말한다. 수동태는 행위자를 모르거나 행위자가 요점과 상관없을 때만 괜찮다.
- 지시는 명령문으로 쓴다. 조건은 지시 앞에, 흔한 경우는 먼저 둔다.
- 유행어도, 비유적 표현도, "please"도 쓰지 않고, 절차에서는 "simply", "easy", "quickly"를 절대 쓰지 않는다.
- 미리 예고하지 않고, 연이은 문장을 같은 구절로 시작하지 않는다.
- 링크는 어디로 가는지 말하는 단어로 건다.
- 헤딩은 요점을 싣고 문장형 대소문자(sentence case)로 쓴다. 페이지당 h1은 하나, 단계를 건너뛰지 않는다.
- 순서가 있으면 번호 목록, 나머지는 글머리표 목록이다. 목록은 완전한 문장으로 소개한다. 항목은 형태를 나란히 맞춘다.
- 코드는 코드 글꼴로, UI 요소는 굵게 쓴다. 연속 쉼표(serial comma)를 쓴다. "etc."는 뺀다.

## 문장이 한 번에 하나씩 실리게 한다 (STE 규칙)

- 지시문은 한 문장에 지시 하나, 그 밖의 문장은 한 문장에 생각 하나다.
- 약 20단어가 넘는 지시문과 약 25단어가 넘는 그 밖의 문장은 나눈다.
- 경고나 조건은 그것이 지키는 단계 앞에 둔다.
- "the"와 "a"를 남긴다.
- 단어마다 뜻 하나를 주고, 동작마다 단어 하나를 고른다.
- 절차는 직접 명령문으로 쓴다. 서술로도, 수동태로도 쓰지 않는다.
- 할 수 있으면 "-ing" 단어를 피한다.

## 두 가지로 읽히는 문장을 남기지 않는다 (Global English)

- "only", "not" 같은 단어는 꾸미는 단어 바로 옆에 둔다.
- 긴 명사 나열을 푼다.
- "it", "they", "this"가 모두 분명한 대상 하나를 가리키게 한다. "this"나 "which"로 절 전체를 가리키지 않는다.
- 동사도, "that"처럼 구조를 보여 주는 작은 단어도 빼먹지 않는다.
- 나열에서 오독을 막을 수 있으면 관사를 반복한다. "and"나 "or"가 어느 부분을 잇는지 밝힌다.
- 세미콜론이나 em대시 대신 마침표를 쓴다. 슬래시도, "(s)"도 쓰지 않는다. 괄호 안의 글은 완전한 문법 단위로 쓴다.
- 한 대상은 어디서나 한 이름으로 부른다.
- 관용구, 구어, 라틴어 약어, 은유를 뺀다.

## 문체와 레포별 사항

- 이 스킬이 손대는 모든 문서에 **unslop** 스킬을 적용한다. 그 스킬이 슬롭 패턴 목록을 가지고 있다. AI 어휘, 군더더기, 얼버무림, 서식 티 같은 것이다.
- PR 설명과 커밋 메시지도 글이다. Diátaxis를 뺀 모든 계층이 적용된다. PR 본문은 리뷰어가 1분 안에 읽을 수 있는 브리핑이다. swarm 로그, SHA 목록, 지표 표를 붙여 넣지 않는다. 링크한다.
- 제품 UI 문자열은 문서가 아니다. 그런 문자열에는 제품의 카피 가이드라인을 쓴다.
- 코드 조각은 탭으로 들여쓴다. 실제 경로를 쓴다. 개수나 트리에 관한 주장은 그 주장이 들어가는 커밋 시점에 사실이어야 하고, 그것을 다시 만들어 내는 명령을 함께 적는다.
