# 공유 상태는 직렬화하기 전에 분리한다

동시에 움직이는 행위자들이 같은 파일, 브랜치, 키, 객체에 쓸 수 있다면, 먼저 그들에게 공유 객체 하나가 필요한지, 아니면 서로 독립된 사실을 내보내는 것인지 묻는다. 기본은 행위자마다 자기 파일, 키, 브랜치, 상태 디렉터리를 주고 상태를 읽는 곳에서만 합치는 것이다. worker 둘이 `state.json` 하나에 각자의 필드를 쓰는 것도 여전히 공유 변경이다.

공유 쓰기 대상 하나가 진짜 불변식일 때만 접근을 구조적으로 직렬화한다(lockfile, 단일 작성자, 순차 단계, compare-and-swap). 지시는 동시성 제어가 아니고, "lock이 필요하다"는 먼저 점검해야 할 냄새다.
