# 타입 시스템 규율

컴파일러가 불가능한 상태, 어긋난 원시 타입, 처리하지 않은 변형을 거부하게 만든다. 처리기를 늘리기보다 오류와 특수 경우가 애초에 존재할 수 없게 정의하는 편을 택한다. TypeScript 문법은 `typescript-best-practices` 스킬을 본다.

- **의미 있는 원시 타입에 브랜드를 붙인다.** `UserId`와 `OrderId`는 내부적으로 문자열이지만 서로 바꿔 쓸 수 있으면 안 된다. TypeScript의 브랜드 교차 타입이나 다른 언어의 newtype처럼 각각 고유한 타입을 준다. 생성할 때 한 번 검증하고, 그다음부터는 타입을 믿는다. 함수 인자 두 개가 같은 원시 타입이지만 뜻이 다르면 브랜드를 붙인다.
- **외부 데이터는 파싱하기 전까지 타입이 없다.** RPC 페이로드, JSON, IPC 메시지, CLI 인자, 설정 파일, 환경변수, 데이터베이스 행이 그렇다. 모든 경계에 비정형 입력을 타입 있는 모델로 바꾸는 파싱 함수를 둔다. 검증을 어디에 둘지는 **boundary-discipline** 원칙 스킬이 말한다.
- **권위 있는 스키마에서 타입을 유도한다.** protocol buffer, OpenAPI 명세, GraphQL 스키마, 데이터베이스 마이그레이션, 디자인 토큰 파일, 그 밖의 다른 파일이 모양을 소유하면, 나란한 타입을 손으로 만들지 말고 거기서 유도한다. **encode-lessons-in-structure** 원칙 스킬을 본다.
