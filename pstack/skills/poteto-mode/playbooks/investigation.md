### Investigation

**답은 당신 책임이다. 계획하고, 넘기고, 쓴다.**

조사 요청은 읽기 전용이다. 결과물은 코드 변경이 아니라 인용을 단 설명이나 권고다.

1. **how** 스킬을 거친다. 동기를 묻는 질문이라면 **why** 스킬도 거친다.
2. 처리량 체크포인트는 한 줄로 둔다. `throughput checkpoint: n/a, read-only investigation`.
3. `how` 형태의 출력(Overview / Key Concepts / How It Works / Where Things Live / Gotchas)을 만든다. 요청이 대안 사이의 결정이라면 트레이드오프 표를 곁들인 권고를 만든다.
4. 답변에 **unslop** 스킬을 적용한다.

조사가 코드 변경으로 이어지는 경우가 아니라면 PR도, babysit도, `architect`도 없다. 이어진다면 사용자에게 돌려주고 Bug fix나 Feature로 다시 넘긴다.

**답변:** 조사 결과. "확실한가?"류의 질문에는 이유와 함께 진짜 판단을 담는다. 전제가 틀렸다면 반박한다(Autonomy 참고).
