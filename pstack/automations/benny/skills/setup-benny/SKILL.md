# Benny 설정

Benny는 pstack 안에 잠든 자동화 팩으로 들어 있다. 플러그인 매니페스트는 pstack의 일반 스킬 루트만 노출하므로, 이 파일과 두 운영 파일은 슬래시 스킬이 아니다.

사람은 Cursor에게 팩의 `FOR_AGENTS.md`를 가리키는 것으로 설정을 시작한다. 부트스트랩 흐름은 팩 전체를 대상 저장소로 복사한 뒤, 이 파일을 `.cursor/automations/benny/skills/setup-benny/SKILL.md`에서 직접 읽는다.

Benny에는 외부 설정과 실제로 동작하는 Cursor 자동화 두 개가 필요하다.

사용자가 명시적으로 요청하기 전에는 자동화를 만들거나 수정하지 않는다. 비밀 값은 플러그인 파일, 프롬프트, 커밋되는 설정 어디에도 넣지 않는다.

## 1. 팩 복사와 공용 pstack 스킬 활성화

Benny 설정을 묻기 전, 그리고 내장 `/automate` 스킬을 호출하기 전에 이 단계를 한다.

자동화를 실행할 저장소가 어디인지 묻는다. 원본 팩은 `FOR_AGENTS.md`가 들어 있는 디렉터리다. 목적지는 `<target-repository>/.cursor/automations/benny/`다.

원본 팩 전체를 목적지에 병합한다.

1. 목적지가 없으면 만든다.
2. 원본의 모든 파일을 같은 상대 경로로 복사한다.
3. 목적지에만 있는 파일은 보존한다. 설치나 갱신 중에 관련 없는 파일을 지우지 않는다.
4. 사용자 소유 설정, 기능 맵(feature map), 라우팅 맵은 목적지 밖에 둔다. 절대 덮어쓰지 않는다.
5. 원본이 관리하는 기존 파일이 다르면 diff를 살피고 로컬 수정을 버리지 않게 병합한다. 소유가 모호하면 교체하기 전에 멈추고 묻는다.
6. 목적지에 `FOR_AGENTS.md`, 이 설정 파일, 두 운영 파일과 그 참조 파일, 템플릿이 모두 있는지 확인한다.

이 파일을 이미 대상 목적지에서 읽고 있다면 복사가 끝난 것으로 보고, 같은 확인을 거친 뒤 계속한다.

대상 저장소의 `.cursor/settings.json`에 pstack을 추가한다. 파일이나 `.cursor` 디렉터리가 없으면 만든다.

기존 JSON 또는 JSONC에 다음 항목을 병합한다.

```json
{
	"plugins": {
		"pstack": { "enabled": true }
	}
}
```

관련 없는 최상위 설정과 다른 플러그인 항목은 모두 보존한다. `plugins.pstack`이 이미 있으면 `enabled` 값만 바꾼다. 파일이 JSONC라면 주석과 올바른 JSONC 문법을 보존한다. 수정한 뒤에는 파일을 검증한다.

대상 프로젝트를 다시 불러오거나 그곳을 루트로 새 에이전트를 시작한다. 다음 공용 pstack 스킬이 프로젝트 범위에서 해석되는지 확인한다.

- `how`
- `why`
- `tdd`
- `unslop`
- `principle-separate-before-serializing-shared-state`
- `principle-minimize-reader-load`
- `principle-guard-the-context-window`
- `principle-sequence-verifiable-units`
- `principle-fix-root-causes`
- `principle-prove-it-works`

현재 세션이나 사용자 범위 플러그인에서 불러온 스킬은 세지 않는다. 대상 저장소의 새 에이전트가 프로젝트 설정으로 pstack을 받는다는 것을 확인해야 한다.

프로젝트 범위 플러그인 설치를 쓸 수 없거나 공용 의존성 중 하나라도 해석되지 않으면 멈추고 실패를 설명한다.

Benny 파일은 `.cursor/automations/benny/`에서 직접 읽는다. 이 디렉터리를 플러그인 매니페스트에 추가하지 않으며, 그 안의 `SKILL.md` 파일이 슬래시 스킬 목록에 나타나리라 기대하지 않는다.

두 자동화 중 어느 것이든 활성화하기 전에 `.cursor/settings.json`, `.cursor/automations/benny/`, 그리고 참조하는 비밀 없는 설정 파일을 커밋해야 한다고 사용자에게 알린다. 사용자가 요청하지 않으면 직접 커밋하지 않는다.

이 확인을 통과하면 실제 자동화 프롬프트는 커밋된 운영 파일을 저장소 기준의 고정 상대 경로로 읽어도 된다. 플러그인 캐시 경로를 넣거나 파일 내용을 복사해 넣어서는 안 된다.

## 2. 설정 맞추기

복사된 다음 예시 파일을 연다.

- `../../templates/configuration.example.yaml`
- `../reproduce-and-fix-issues/references/feature-map.example.md`

`.cursor/automations/benny/` 밖에 사용자 소유 사본을 만든다. 이들은 팩 파일이 아니라 설정 파일이다. 위치 예시는 다음과 같다.

- 프로젝트 설정, 예: `.cursor/benny/configuration.yaml`
- 프로젝트 기능 맵, 예: `.cursor/benny/feature-map.md`
- 프로젝트 라우팅 맵, 예: `.cursor/benny/routing.md`
- 사용자 설정, 예: `~/.config/benny/configuration.yaml`
- 사용자 기능 맵, 예: `~/.config/benny/feature-map.md`

자동화가 재현할 수 있는 사용자 대상 기능마다 기능 맵 섹션을 하나씩 채운다. 사용자 관점을 유지한다. 구현 세부나 현재 코드 경로를 맵에 박아 두지 않는다.

복사된 예시 파일은 수정하지 않는다. 팩 갱신은 충돌 검토를 거쳐 원본 관리 파일을 바꿀 수 있지만, 사용자 소유 사본은 절대 건드려서는 안 된다.

새로 체크아웃한 자동화가 읽어야 하는 파일이라면 대상 저장소에 커밋된 비밀 없는 파일을 우선한다. 그렇지 않으면 필요한 값을 실제 프롬프트에 풀어 쓴다. 저장소 파일은 자동화가 실행될 저장소에 그 파일이 커밋되어 있음을 내장 `/automate` 스킬이 확인한 뒤에만 참조한다.

커밋된 팩 파일과 설정 파일은 저장소 기준의 고정 상대 경로로 쓴다. 실제 자동화에서 플러그인 원본 디렉터리나 플러그인 캐시 경로를 참조하지 않는다.

## 3. 필수 선택지 채우기

다음을 묻거나 확인한다.

- 원본 Slack 채널 ID
- 선택 사항인 운영·상태 채널 ID
- 저장소 URL과 기본 브랜치
- triage 신원 또는 Slack 사용자 ID
- 이슈 트래커 종류, 팀, 프로젝트, 라벨, 접수 상태
- 트래커 어댑터 스킬 또는 MCP 액션
- 선택 사항인 라우팅 맵 경로
- 필수인 제어 스킬 이름
- 필수인 사용자 대상 기능 맵 경로
- 상태 이모지 문자열
- 풀 리퀘스트 URL 형식
- 폴링과 작업량 예산
- triage, repro, 코드 작업, 미디어 검토에 쓸 모델 slug

사용자의 Cursor 모델 선택기나 지원 모델 목록에 사용 가능으로 표시된 모델 slug만 쓴다. slug를 추측하지 않고, 비공개 기본값을 그대로 가져오지도 않는다.

원본 채널, triage 신원, 저장소, 트래커 어댑터, 제어 스킬, 기능 맵은 명시적이어야 한다. 필수 값이 하나라도 모호하게 남으면 설정을 실패 처리한다.

자동화 이름, 설명, 프롬프트 shim을 저장하기 전에 최종본에 pstack의 `unslop` 스킬을 적용한다.

## 4. 연동 기능 확인

triage 자동화에 필요한 것은 다음과 같다.

- 설정된 원본 Slack 채널과 그 스레드 읽기 권한
- 그 채널의 스레드 답글 권한
- 보고에 미디어가 포함될 때 첨부 메타데이터와 파일 다운로드 권한
- 설정된 이슈 트래커 어댑터를 거친 검색, 읽기, 생성, 수정 권한

repro 자동화에 필요한 것은 다음과 같다.

- 원본 스레드 읽기 권한
- 원본 채널의 스레드 답글 권한
- 선택 사항인 설정된 운영 채널의 게시·수정 권한
- 저장소 읽기와 히스토리 접근 권한
- 드래프트 풀 리퀘스트를 열 수 있는 풀 리퀘스트 액션
- 설정된 제어 어댑터 스킬

읽기와 게시에는 설정된 Cursor Slack 액션을 우선한다. 선택 사항인 `BENNY_SLACK_BOT_TOKEN`은 운영 상태 메시지 하나를 수정하거나 첨부 파일을 내려받는 것처럼 좁은 빈틈만 메울 수 있다. 값은 YAML이 아니라 비밀 관리자나 환경 변수에 저장한다.

문서화되지 않은 연동 엔드포인트는 쓰지 않는다.

## 5. 라우팅 맵 준비

사용자가 재배정이나 담당자 호출을 원한다면 다음을 한다.

1. `../triage-issue-reports/references/routing.example.md`를 `.cursor/automations/benny/` 밖으로 복사한다.
2. 모든 자리표시자를 공개 값이나 조직 내부 값으로 바꾼다.
3. 담당자 호출은 기본적으로 꺼 둔다.
4. 설정된 기능 담당자나 확인된 회귀 유력 작성자에게만 호출을 허용한다.

라우팅 맵이 설정되지 않았다면 triage는 보고를 분류할 수는 있지만 목적지나 담당자를 추측해서는 안 된다.

## 6. 제어 어댑터 확인

`../reproduce-and-fix-issues/references/control-adapter.md`와 사용자가 완성한 기능 맵을 읽는다.

지정된 스킬이 다음을 할 수 있는지 확인한다.

- 대상 앱 띄우기
- 매핑된 모든 기능을 실제 UI로 탐색하기
- 선언된 어댑터 액션으로 매핑된 상태 실행하기
- 결과를 강제하지 않고 상태 살펴보기
- 스크린샷 찍기
- 녹화 시작과 중지
- 자신의 프로세스와 임시 데이터 정리

하나라도 빠지면 repro 자동화를 비활성 상태로 둔다. 하지 않은 재현을 했다고 주장하기보다 닫힌 채로 실패해야 한다.

## 7. 실제 자동화 준비

처음 만드는 것인지, 기존 자동화를 설정하는 것인지 묻는다.

어느 경로든 복사된 팩의 `../../FOR_AGENTS.md`를 사용자 의도의 1차 출처로 읽는다. 이를 바탕으로 두 트리거, 도구, 지시, 결과, 공통 규칙을 파악한다.

### 처음 만들기

자동화는 한 번에 하나씩 만든다.

각 자동화마다 다음을 한다.

1. 대응하는 복사된 프롬프트 템플릿을 2차 내부 자료로 읽는다.
2. `FOR_AGENTS.md`, 완성된 Benny 설정, 템플릿 의도를 완결된 자연어 요청으로 바꾼다.
3. 실제 프롬프트가 `.cursor/automations/benny/` 아래 커밋된 정확한 운영 파일을 읽고 따르도록 지시한다.
4. 플러그인 원본이나 캐시 경로가 아니라 저장소 기준 고정 상대 경로를 쓴다. 운영 파일 내용을 실제 프롬프트에 복사하지 않는다.
5. 내장 `automate` 스킬을 읽고 따른다.
6. Slack 채널, 저장소, 연결된 연동은 `automate`가 찾게 둔다.
7. 복사된 팩과 참조하는 설정 파일이 자동화가 실행될 저장소에 커밋되어 있는지는 `automate`가 확인하게 둔다.
8. 초안 표를 보여 주고, 승인을 받고, 준비 여부를 묻고, Automations 편집기를 여는 일은 `automate`가 하게 둔다.
9. 다음 자동화를 시작하기 전에 이 자동화의 편집기 인계를 마친다.

설정값으로 채운 다음 triage 의도를 빠짐없이 `automate`에 넘긴다.

- 이름은 `benny-triage`.
- 매 실행마다 `.cursor/automations/benny/skills/triage-issue-reports/SKILL.md`를 읽고 따른다.
- 설정된 원본 Slack 채널에 새 최상위 보고가 올라올 때마다 트리거한다.
- 트리거한 스레드를 읽고, 그 스레드 안에서만 답한다.
- 설정된 이슈 트래커 연동을 쓴다.
- 분류하고, 증거를 살피고, 원인을 추적하고, 중복을 제거하고, 명확한 새 버그만 생성한다.
- 스레드에만 다는 판정 하나를 설정된 `[benny:bug]`, `[benny:performance]`, `[benny:other]` 마커와 선택 사항인 트래커 URL로 끝낸다.
- 원본 채널에 루트 메시지를 절대 올리지 않는다.

triage 편집기 인계가 끝나면 다음 repro·수정 의도를 빠짐없이 `automate`에 넘긴다.

- 이름은 `benny-reproduce`.
- 매 실행마다 `.cursor/automations/benny/skills/reproduce-and-fix-issues/SKILL.md`를 읽고 따른다.
- 설정된 원본 Slack 채널의 같은 새 최상위 보고에 트리거한다.
- 설정된 저장소와 기본 브랜치를 쓴다.
- 원본 스레드를 읽고, 그 스레드 안에서만 답한다.
- 풀 리퀘스트 생성, 그리고 설정된 트래커, 제어 어댑터, 기능 맵 요구 사항을 포함한다. 같은 저장소에 커밋된 적격 파일을 `automate`가 확인하지 않는 한 매핑된 사용자 경로와 상태는 풀어 쓴다.
- 행동하기 전에 신뢰할 수 있는 triage 마커를 기다린다.
- 매핑된 실제 UI로 정확한 증상을 두 번 재현하고 증거를 남긴다.
- 이미 있는 수정은 덮어쓰지 않고 검증한다.
- 선택 사항인 범위 제한 수정은 재현이 확인된 뒤에만 시도하고, 증명과 검사를 통과하면 드래프트 풀 리퀘스트를 연다.
- 원본 채널에 루트 메시지를 절대 올리지 않는다.

`automate`가 하는 Slack, 저장소, 연동, 완결성, 인증, 초안 검토, 승인, 준비 여부, 편집기 인계 작업을 중복하지 않는다.

### 기존 자동화

내장 `automate` 스킬은 생성 전용이다. 기존 자동화를 찾거나 살피거나 수정하는 데 쓰지 않는다.

설정, 라우팅, 제어 어댑터, 기능 맵 검증을 마친다. 그런 다음 사용자에게 다음의 간결한 편집기 체크리스트를 준다.

기존 triage 자동화에서 수정할 것은 다음과 같다.

- 이름과 설명
- `.cursor/automations/benny/skills/triage-issue-reports/SKILL.md`를 읽으라는 직접 지시
- 새 최상위 Slack 보고 트리거와 원본 채널
- Slack 스레드 읽기·답글 기능
- 이슈 트래커 연동
- 풀어 쓴 triage 지시, 스레드 전용 규칙, Benny 판정 마커

기존 repro 자동화에서 수정할 것은 다음과 같다.

- 이름과 설명
- `.cursor/automations/benny/skills/reproduce-and-fix-issues/SKILL.md`를 읽으라는 직접 지시
- 짝이 맞는 Slack 트리거와 원본 채널
- 저장소와 기본 브랜치
- Slack 스레드 읽기·답글 기능
- 풀 리퀘스트 액션
- 트래커, 제어 어댑터, 기능 맵 요구 사항
- 풀어 쓴 마커 대기, 증거, 검증, 범위 제한 수정 지시

각 기존 자동화는 해당 Automations 편집기에서 사용자가 직접 수정하도록 요청한다. 대체본이나 중복본을 만들지 않는다.

### 생성 경계

자동화 백엔드 서비스나 백엔드 자동화 도구를 직접 호출하지 않는다. 초안 필드를 담은 브라우저 URL을 쓰지 않는다. Cursor 프로토콜 딥 링크를 만들거나 열지 않는다. 새 자동화를 마무리하는 경로는 내장 `automate` 스킬이 검토를 거쳐 넘기는 Automations 편집기 인계 하나뿐이다.

편집기에 저장한 뒤 스레드 안전성 테스트를 통과하기 전에는 어느 자동화도 활성화하지 않는다.

## 8. 스레드 안전성 테스트

테스트 채널이나 무해한 테스트 보고를 쓴다.

테스트 전에 대상 저장소의 `.cursor/settings.json`, `.cursor/automations/benny/`, 참조하는 모든 비밀 없는 설정 파일이 자동화 체크아웃이 쓰는 브랜치에 커밋되어 있는지 확인한다. 두 실제 프롬프트가 커밋된 정확한 운영 파일을 가리키는지 확인한다. 하나라도 실패하면 멈추고, 아직 자동화를 활성화할 수 없다고 사용자에게 알린다.

다음을 확인한다.

1. triage가 루트 `thread_ts`를 저장하고 정확히 하나의 판정을 답글로 올린다.
2. 판정에 설정된 마커가 하나 들어 있다.
3. repro는 설정된 triage 신원이 단 마커만 받아들인다.
4. repro는 불변인 원본 좌표를 그대로 유지한다.
5. 원본 채널에 루트 메시지가 나타나지 않는다.
6. 위임받은 worker는 어떤 Slack 쓰기 액션도 쓸 수 없다.
7. 좌표 누락, 삭제된 부모 메시지, 실패한 사전 점검은 게시도 트래커 이슈도 만들지 않는다.

일곱 가지 확인을 모두 통과한 뒤에만 정상 트래픽을 켠다.
