# 기초적 사고

**구조적 결정**은 선택지의 가치를 지킨다. **코드 수준 결정**은 단순함을 지킨다.

**자료구조가 먼저다.** 로직을 쓰기 전에 데이터 형태를 제대로 잡는다. 핵심 타입을 일찍 정의하고, 모든 접근 패턴을 추적하고, 주된 경로에 맞는 구조를 고른다.

코드 수준에서는 모든 줄이 아니라 구조를 DRY하게 만든다. 타입과 데이터 모델은 하나로 수렴해야 한다. 그래도 비슷한 문장 세 개가 섣부른 추상보다 낫다. 영리함보다 명시성을 택한다. 줄 수가 아니라 동작과 엣지 케이스를 테스트한다.

**동시성 따름정리.** 주체들 사이에 상태를 공유하기 전에 "다른 주체가 이것을 동시에 수정하면 어떻게 되나?"를 묻는다. 답이 "아무 일도 없다"가 아니면 격리한다.

**뼈대가 먼저다.** 이후의 모든 단계에 도움이 되는 것이 있다면 그것부터 한다. "이것이 있으면 이후 모든 단계가 득을 보나?"를 묻는다. CI, lint, 테스트 인프라, 공유 타입이 뼈대다. 선택지의 가치를 기준으로 순서를 정한다. 기능보다 설정을 먼저, 수정보다 테스트를 먼저 한다. 커밋은 작고 목적이 하나여야 한다.

각 증분은 일관된 추상 하나를 반영하거나 기존 추상을 깊게 만들어야 한다. 새 기능을 특수 사례 조율 코드로 호출자들에게 흩뿌리지 않는다.

빼기가 뼈대보다 먼저다. 죽은 코드를 먼저 지우고 그다음 기초를 놓는다.
