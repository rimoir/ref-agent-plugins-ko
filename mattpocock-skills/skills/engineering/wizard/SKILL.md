# 마법사(wizard)

**마법사(wizard)** 는 사람이 손으로 하기 번거롭고 AI에게 매번 다시 설명하기도 번거로운 수동 절차를 한 단계씩 안내하는 bash 스크립트다. 각 URL을 열고, 무엇을 클릭하고 복사할지 정확히 알려 주고, 값을 받아서 들어갈 자리(`.env`, GitHub 시크릿)에 쓰고, 단계마다 확인을 받고, 남은 단계가 몇 개인지 보여 준다. 외부 서비스를 설정하거나, 한 번만 하는 마이그레이션을 실행하거나, 프로젝트를 한 상태에서 다른 상태로 옮기는 데 쓸 수 있다.

사용하기 편한 UX는 [template.sh](template.sh)에 이미 들어 있다. 단계별 진행 표시, 확인 절차, 여러 플랫폼(WSL 포함)에서 URL 열기, 시크릿 입력 숨기기, 여러 번 실행해도 결과가 같은 `.env` 갱신, `gh secret`/`gh variable` 쓰기, 마지막 요약이 모두 있다. **네가 할 일은 절차의 범위를 정하고 그 단계들을 작성하는 것뿐이다.** `STAGES` 표시 위쪽의 라이브러리는 모든 마법사에서 똑같다. 모든 마법사가 같은 라이브러리를 쓰는 것이 핵심이므로 이 부분을 절대 손으로 고치지 마라.

마법사는 기본적으로 일회용이다. 한 번 실행하려고 만들고, 임시 경로나 `scripts/` 경로에 저장하고, 작업이 끝나면 지운다. 저장소에 두고 반복해서 쓸 설정 경로를 사용자가 원할 때만 커밋한다.

## 절차

### 1. 절차의 범위 정하기

사람이 직접 해야 하는 수동 단계와 그 과정에서 받아야 하는 값을 모두 파악한다. 사용자에게 바로 묻지 말고 저장소부터 읽는다.

- 설정 작업이면 `.env`, `.env.example`, `.env.*`, `README`, `docker-compose*`, 프레임워크 설정, `.github/workflows/*`를 읽는다(`secrets.*` / `vars.*` 참조 하나하나가 마법사가 만들어야 할 값이다).
- 마이그레이션이나 전환 작업이면 현재 상태, 목표 상태, 그 사이에 있는 되돌릴 수 없는 작업을 파악한다.

그런 다음 단계 목록을 순서대로, 각 단계가 만드는 값과 함께 사용자에게 보여 주고 확인을 받는다. 사용자는 단계를 추가하거나 빼거나 순서를 바꿀 수 있다.

**완료 기준:** 모든 단계에 순서대로 이름이 붙어 있고, 받아야 하는 값마다 (a) 사람이 그 값을 어디서 얻는지, (b) 그 값을 어디에 쓰는지(`.env`, GitHub 시크릿, 둘 다, 또는 아무 데도 쓰지 않는다. 동작만 하는 단계도 있다), (c) 시크릿인지(입력을 숨긴다) 공개 값인지 알고 있다.

### 2. 단계마다 사람이 따라갈 경로 정리하기

단계마다 사람이 따라갈 정확한 경로를 쓴다. 어떤 URL을 열고, 거기서 무엇을 하고, 값이 어디에 표시되고, 그 값이 어떤 변수에 들어가는지 적는다. 예: "Dashboard → Developers → API keys → Reveal test key → copy". 현재 UI나 정확한 명령을 실제로 모르면 모른다고 말하고 사용자에게 묻거나 문서를 확인한다. 존재하지 않을 수도 있는 단계를 절대 지어내지 마라.

**완료 기준:** 모든 단계가 처음 보는 사람도 따라 할 수 있는 구체적인 안내로 이어진다.

### 3. 마법사 작성하기

`template.sh`를 목표 경로로 복사한다. 예시 단계를 지우고 수동 단계 하나마다 `stage` 하나를 의존 순서대로 넣는다. 라이브러리 헬퍼 `stage`, `say`/`step`, `open_url`, `ask`/`ask_secret`, `write_env`, `set_secret`/`set_var`, `pause`/`confirm`을 쓴다. `TOTAL_STAGES`를 작성한 단계 수로 맞춘다.

템플릿이 정한 기준을 지킨다. 값을 묻기 전에 그 값이 있는 URL을 먼저 열고, 시크릿은 모두 `ask_secret`으로 받고, 저장해야 하는 값은 모두 `write_env`로 쓰고, `set_secret`은 CI에 실제로 필요한 값에만 쓰고, 되돌릴 수 없는 작업 앞에는 `confirm`을 둔다. `stage`는 실행될 때마다 화면을 지워 현재 단계만 보이게 하므로, 한 단계에는 작업 하나만 담아 사람이 봐야 할 내용이 화면 밖으로 밀려나지 않게 한다. 표시 위쪽의 라이브러리는 건드리지 마라.

### 4. 검증하고 인계하기

- `bash -n <script>`를 실행하고, `shellcheck`가 있으면 그것도 실행한다.
- `chmod +x <script>`를 실행한다.
- 스크립트를 처음부터 끝까지 직접 실행하지 마라. 브라우저를 열고 사람의 입력을 기다리며 멈춘다. 대신 코드를 읽어 정적으로 따라간다. 1단계에서 정한 값을 모두 입력받아 1단계에서 정한 자리에 쓰는지, `set_secret`의 이름이 모두 CI의 `secrets.*` 참조와 정확히 일치하는지 확인한다.
- 사용자에게 실행 방법을 알려 준다. 반복해서 쓸 설정 경로라면 커밋하고 README에서 링크해, 다음 사람이 AI에게 묻지 않고 이 스크립트를 실행하게 한다.
