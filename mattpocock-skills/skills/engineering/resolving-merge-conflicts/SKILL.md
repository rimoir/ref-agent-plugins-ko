---
name: resolving-merge-conflicts
description: "진행 중인 git merge/rebase 충돌을 해결해야 할 때 쓴다."
---

1. merge/rebase의 **현재 상태를 확인한다**. git 기록과 충돌한 파일을 살펴본다.

2. 충돌마다 **1차 자료를 찾는다**. 각 변경을 왜 했는지, 원래 의도가 무엇이었는지 깊이 이해한다. 커밋 메시지를 읽고, PR을 확인하고, 원래 이슈나 티켓을 확인한다.

3. **변경 블록(hunk)을 하나씩 해결한다**. 가능하면 양쪽 의도를 모두 살린다. 두 의도가 함께 성립할 수 없으면 이 merge가 밝힌 목표에 맞는 쪽을 고르고, 포기한 부분을 기록한다. 새 동작을 만들어 넣지 **않는다**. 항상 해결한다. `--abort`는 절대 쓰지 않는다.

4. 프로젝트의 **자동 검사**를 찾아 실행한다. 보통 타입 검사, 테스트, 포맷 순서다. merge 때문에 깨진 것은 모두 고친다.

5. **merge/rebase를 마무리한다**. 모든 변경을 스테이징하고 커밋한다. rebase 중이라면 모든 커밋이 rebase될 때까지 rebase를 계속 진행한다.
