# 모델 호출과 사용자 호출

이 저장소의 모든 `SKILL.md`는 스킬이다. 스킬을 나누는 기준은 **호출 방식**, 곧 누가 그 스킬을 호출할 수 있는가 하나뿐이다.

- **사용자 호출**(User-invoked): **사람이 이름을 입력해야만** 호출할 수 있다. frontmatter에 `disable-model-invocation: true`(Claude Code)를, `agents/openai.yaml`에 `policy.allow_implicit_invocation: false`(Codex)를 설정한다. `description`은 **사람이 읽는** 글이다. 슬래시 명령 목록을 훑어보는 사람이 읽는 한 줄 요약으로 쓴다. 트리거 목록("사용자가 …라고 하면 쓴다" 같은 문구)은 뺀다.
- **모델 호출**(Model-invoked): **모델도 사용자도** 호출할 수 있다. 기본값이다. `disable-model-invocation`을 쓰지 않고 `agents/openai.yaml`에서 `policy` 블록도 뺀다. `description`은 **모델이 읽는** 글이고, 자동 호출이 일어나도록 트리거 문구("사용자가 …를 원하거나, …를 언급하거나, …를 요청할 때 쓴다")를 풍부하게 담는다. 스킬을 모델 호출로 둘지 판단하는 기준은 _모델이 스스로 이 스킬을 꺼내 쓰는 것이 도움이 되는가_라는 질문이다. (재사용은 스킬을 따로 뽑아내는 이유이지 이 판단 기준이 아니다.)

하네스마다 방식은 다르지만 모두 사용자 호출 스킬을 모델이 호출할 수 없게 막는다. 그래서 이런 스킬은 사람만 실행할 수 있고 다른 스킬은 호출할 수 없다. 사용자 호출 스킬은 모델 호출 스킬을 호출할 수 있지만 다른 사용자 호출 스킬은 절대 호출할 수 없다.

모든 스킬에는 `SKILL.md` 옆에 `agents/openai.yaml`도 있다. 이 파일은 Codex UI 메타데이터를 담는다. 스킬 선택 화면에 쓰는 `interface.display_name`과 `interface.short_description`이 있고, 사용자 호출 스킬이라면 `disable-model-invocation`과 짝을 이루는 `policy.allow_implicit_invocation: false`도 있다. 이 둘을 항상 맞춘다. 스킬은 두 하네스 모두에서 사용자 호출이거나 둘 다에서 사용자 호출이 아니어야 한다.

버킷의 `README.md`와 최상위 `README.md`는 항목을 **사용자 호출**(User-invoked)과 **모델 호출**(Model-invoked)로 묶는다.

## 스킬 사이의 의존 관계

의존 관계는 이름을 밝힌 스킬로 **Skill 도구를 호출하라**는 명시적 지시로 표현한다(`Skill 도구로 "grilling"을 호출한다`). `../other-skill/FILE.md` 같은 깊은 교차 참조로 쓰지 않고, 모델이 알아서 해석하도록 `/skill` 형태의 이름만 적어 두지도 않는다. 도구 이름을 밝혀야 실제로 호출된다. 대부분의 하네스는 스킬 호출을 모델이 부르는 도구로 제공하므로, 그 점을 적어 두면 산문에 `/name`을 넣고 명령으로 읽히기를 기대할 때보다 호출될 확률이 높다. 앞의 `/`를 빼도 하네스 중립성이 떨어지지 않고, 오히려 특정 하네스에 묶이지 않게 된다. 스킬 이름만 쓰면 어느 하네스의 호출 문법인지 전제하지 않는다. 여러 스킬이 함께 쓰는 참고 문서는 그 문서를 가진 스킬 안에 둔다. 다른 스킬은 폴더를 넘나드는 링크가 아니라 그 스킬로 Skill 도구를 호출해 자료를 얻는다.

이 규칙은 **실행 지시**에 적용한다. 스킬의 단계가 에이전트에게 지금 바로 다른 스킬을 실행하라고 시키는 경우다. 사람이 고를 수 있도록 스킬 이름만 나열하는 안내 문장(`ask-matt`, 버킷 `README.md`)은 아무것도 호출하지 않으므로 `/skill` 형태의 이름을 단순한 표시로 그대로 쓴다.

Skill 도구는 한 번 호출할 때 스킬 하나만 받는다. 스킬 두 개가 필요한 단계는 이름 두 개를 넣은 한 번의 호출이 아니라 두 번의 호출이다. 그렇게 적는다(`Skill 도구를 "grilling"으로 한 번, "domain-modeling"으로 한 번, 두 번 호출한다`). "X와 Y로 호출한다"처럼 쓰면 한 번의 호출에 둘을 넣는 것으로 읽히므로 그렇게 쓰지 않는다.

이 규칙 전체는 이름을 밝힌 스킬이 **모델 호출** 스킬일 때만 성립한다. 사용자 호출 스킬은 이 방식으로 절대 호출할 수 없다. 위에서 말한 불변 조건대로 다른 스킬은 이 스킬을 호출할 수 없고, Skill 도구에 이름을 넘기는 방식도 마찬가지다. 어떤 단계의 사전 조건이 사용자 호출 스킬(예: `setup-matt-pocock-skills`)이라면 Skill 도구 호출로 쓰지 말고 사람이 직접 하도록 지시하는 문장으로 쓴다. "사용자에게 `/setup-matt-pocock-skills`를 실행하라고 알린다"처럼 쓴다.

## 수동적인 도메인 작업과 능동적인 도메인 작업

용어를 확인하려고 `CONTEXT.md`를 _읽기만_ 하는 일은 `domain-modeling` 스킬이 아니라 한 줄짜리 안내 문장으로 충분하다. 용어를 만들고 다듬는 능동적인 작업(용어에 이의 제기, 경계 사례 시나리오 검토, ADR 작성, `CONTEXT.md` 즉시 갱신)만 `domain-modeling`이다.
