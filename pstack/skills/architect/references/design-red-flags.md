# 설계 위험 신호

종합하기 전에 모든 후보를 걸러 낸다. 위험 신호(red flag)는 형태를 고치거나 버릴 이유다.

## 얕은 모듈

얕은 모듈(shallow module)은 큰 인터페이스를 드러내면서 숨기는 복잡성은 적다. 깊이는 공개 표면의 크기에 비해 그 뒤에 숨긴 기능과 정책이 얼마나 되는지로 판단한다. 상당한 동작이 뒷받침하는 단순한 인터페이스를 우선한다.

깊은 모듈과 깊은 호출 사슬을 혼동하지 않는다. 깊은 호출 사슬은 이해를 여러 계층에 흩어 놓는다. 깊은 모듈은 인터페이스 하나 뒤에 기능을 모은다.

다음 징후를 찾는다.

- 호출자가 작업 하나를 끝내려고 메서드 여럿을 조율한다.
- 공개 옵션이 내부 단계나 구현 선택을 드러낸다.
- 인터페이스를 배워도 호출자가 구현을 배우는 수고를 덜지 못한다.

## 정보 누출

정보 누출(information leakage)은 여러 모듈이 같은 내부 결정에 의존하게 만든다. 표현, 정책, 프로토콜 세부가 두 곳 이상에 나타나서 그것을 바꾸려면 여러 곳을 맞춰 고쳐야 한다.

전송 타입이나 wire 타입을 공개로 다시 내보내는 것은 누출이다. 외부 데이터는 인터페이스 뒤에서 도메인 타입으로 파싱한다. 저장소 스키마, 프레임워크 객체, 프로토콜 세부는 비공개로 둔다.

## 시간 순 분해

시간 순 분해(temporal decomposition)는 모듈이 소유한 지식이 아니라 실행 순서로 모듈을 나눈다. 불러오기, 검증, 변환, 저장 단계를 따로 두면 표현 하나와 그 불변식이 여러 경계에 걸쳐 반복되는 일이 잦다.

코드는 도메인 지식과 소유권을 중심으로 묶는다. 서로 다른 시점에 도는 메서드라도 같은 결정을 지킨다면 한 모듈에 속할 수 있다.

## 통과 메서드

통과 메서드(pass-through method)는 같은 인자를 같은 형태의 다른 메서드로 그대로 넘긴다. 복잡성은 숨기지 않고 계층만 하나 더한다.

지우거나, 작업을 끝낼 수 있는 모듈로 책임을 옮긴다. 정책, 변환, 별개의 추상화를 더할 때만 전달 경계를 남긴다.
