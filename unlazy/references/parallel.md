# 병렬 파이프라인과 리프

스코프(scope)와 소유권 점유(lease)는 서로 협력하는 unlazy 프로세스들을 조정한다. 한 파이프라인이 실수로 다른 파이프라인의 게이트 파일을 완료로 처리하는 교차 인증을 막고, 선언된 소유권이 겹치면 거부한다(게이트는 완료로 인정하려면 충족해야 하는 조건 한 항목이고, 게이트 파일은 게이트를 적은 파일이다). 셸 명령을 샌드박스에 가두거나, 운영체제 권한을 강제하거나, 이 규약을 무시하는 프로세스가 아무 파일에나 쓰는 것을 막지는 않는다.

## 레이아웃

```text
.unlazy/
  <scope>/
    PLAN.md
    GATES.md
    gates/
      leaf-*.md
      node-*.md
    status.log
    session
    hook-state.json
  locks/
```

`.unlazy/`는 git이 추적하지 않는 상태로 둔다. 레거시 단일 파이프라인 레이아웃, 곧 프로젝트 루트의 `GATES.md`와 `gates/*.md`는 단독 작업에 계속 쓸 수 있다.

## 스코프 결정

스코프를 쓰는 검사기 호출은 다음 순서로 파이프라인 하나를 고른다.

1. `--scope <id>`
2. `UNLAZY_SCOPE`
3. 스코프가 하나뿐이면 그 스코프
4. 스코프 파이프라인이 하나도 없으면 레거시 레이아웃

Stop 훅은 여기에 더해 `--bind`로 기록된 현재 Claude Code `session_id` 바인딩도 쓸 수 있다. 바인딩은 세션을 스코프에 연결할 뿐 인증이 아니다.

스코프가 여러 개 있는데 어느 것으로도 결정되지 않으면 검사기는 모든 게이트 파일을 실행하지 않고 거부한다. Stop 훅은 알 수 없는 파이프라인 때문에 세션을 차단하지 않고, 진단 메시지와 함께 멈춤을 허용한다.

스코프 id는 `[A-Za-z0-9][A-Za-z0-9._-]{0,63}`에 맞고 `.`나 `..`가 아닌 값을 쓴다. 구분자, 경로 이동(traversal), 절대 경로를 쓰지 않는다.

## 스코프가 분리하는 것

스코프가 제한하는 것은 unlazy 자체의 다음 항목이다.

- 기본 게이트 파일 탐색
- 상태 로그 대상
- Stop 훅의 스코프 결정과 진행 상태
- 점유 소유자 이름표

스코프는 `CHECK:` 프로세스를 제한하지 않는다. 검사는 실행 환경이 가진 운영체제 접근 권한을 그대로 물려받아 스코프 밖을 읽거나 쓸 수 있다. 명령 자체를 분리해야 하면 별도 워크트리나 더 강한 프로세스 분리를 쓴다.

## 소유권 선언

첫 게이트 앞에 저장소 루트 기준 상대 경로를 선언한다.

```markdown
OWNS: src/api/**, tests/api/**
```

절대 경로와 `..` 경로 이동 세그먼트가 들어간 경로는 거부한다. 동시에 배정(dispatch)하는 모든 리프(leaf, 트리 맨 아래의 작업 단위)는 자신이 수정할 수 있는 경로를 전부 선언하고, 작업 전에 그 경로를 점유 신청(`--claim`)해야 한다.

```text
node <skill-dir>/scripts/gate-check.mjs --scope api --leaf leaf-1.2.1 --claim
```

점유 신청은 전역 점유 잠금 하나를 잡은 채로 기존 점유를 모두 확인하고 새 점유를 기록한다. 서로 충돌하는 점유 신청 두 개가 동시에 들어와도 둘 다 성공할 수는 없다. 점유 신청은 전부 성공하거나 전부 실패한다.

스코프/리프 이름표는 그 점유가 있는 동안 그 자체로 배타적이다. 같은 점유 신청을 반복하면 새로 요청한 경로가 겹치지 않더라도 거부되고, 거부된 시도는 원래 점유의 OWNS 경로 집합을 절대 다시 쓰지 않는다. 같은 리프를 다시 점유 신청하려면 먼저 바로 그 리프를 해제(`--release`)한다. 이 규칙은 같은 논리적 식별자로 배정된 작업 에이전트 둘이 둘 다 한 점유를 가졌다고 믿는 일을 막는다.

잠금 디렉터리에는 소유자 정보를 담은 JSON 메타데이터가 들어 있다. unlazy는 오래되어 보이는 잠금을 일부러 자동으로 풀지 않는다. 살아 있는 소유자의 경로를 지우면 후속 프로세스 둘이 동시에 들어올 수 있기 때문이다. 프로세스가 잠금을 잡은 채 죽으면, 먼저 잠금에 기록된 프로세스가 더 이상 실행 중이 아니고 그 잠금을 아직 가지고 있을 수 있는 unlazy 작업이 없는지 확인한 뒤, 주인이 없어진 그 잠금 하나만 직접 지운다. 작업이 진행 중일 때 잠금 디렉터리 전체를 비우지 마라. 승인 기록 잠금도 같은 복구 규칙을 따른다.

겹침 판정은 일부러 보수적으로 한다. 완전한 교집합 계산 엔진이라면 겹치지 않는다고 증명할 수 있는 두 glob을 거부할 수도 있고, 세그먼트 중간에 와일드카드가 있는 glob에서 특히 그렇다. 불확실한 쌍을 안전하다고 통과시켜서는 안 된다. 충돌이 과하게 나오면 더 단순하고 서로 겹치지 않는 경로를 쓰거나 순차로 배정한다.

예:

| 첫 번째 선언 | 두 번째 선언 | 결과 |
|---|---|---|
| `src/api/**` | `src/web/**` | 겹치지 않음 |
| `src/shared/**` | `src/shared/util.mjs` | 충돌 |
| `src/a*.mjs` | `src/ab*.mjs` | 교집합이 생길 수 있어 충돌 |
| `**` | `docs/**` | 충돌 |

점유는 선언된 경로만, 그리고 점유를 지키는 참여자만 다룬다. 점유는 조정을 위한 기록이지 쓰기 분리가 아니다.

부모 재검증과 수동 검토를 마친 뒤에는 바로 그 리프만 해제하고, 그 리프에 의존하는 리프를 승격(WAITING에서 READY로 올림)하기 전에 해제를 기록한다.

```text
node <skill-dir>/scripts/gate-check.mjs --scope api --release --leaf leaf-1.2.1
node <skill-dir>/scripts/gate-check.mjs --scope api --log "leaf-1.2.1 lease released"
```

모든 리프가 최종 상태에 이르고, 모든 실행 묶음(wave)이 종료 상태가 되고, 중간 노드(branch) 검증, 루트 검증, 최종 전체 검증까지 실행한 뒤에만 스코프 전체를 해제한다. 그 밖의 경우에는 기록된 소유 프로세스가 사라졌음을 확인한 뒤의 명시적 복구에만 스코프 전체 해제 형식을 쓴다.

```text
node <skill-dir>/scripts/gate-check.mjs --scope api --release
```

알 수 없는 `--leaf`는 오류다. 검사기는 절대 조용히 첫 번째 게이트 파일로 대신하지 않는다.

## 게이트 파일 동시 갱신

검사기는 게이트 파일 갱신을 하나씩 순서대로 처리하고 원자적으로 반영한다. 완료된 검사 결과를 반영하기 전에 게이트 파일을 다시 읽어, 게이트 id와 판정 기준(oracle) 필드가 실행한 내용과 아직 같은지 확인한다. 실행 도중에 명령, 기대값, 작업 디렉터리, 그 밖에 증거에 묶인 판정 기준 필드가 바뀌었으면 최신이 아닌 그 결과는 버린다.

게이트 파일의 원래 LF 또는 CRLF 줄바꿈 방식을 유지한다. 빠진 증거 줄은 관련 없는 내용을 바꾸지 않고 끼워 넣는다. `--jobs <N>`으로 검사를 동시에 실행해도 결과 출력은 게이트 순서대로 결정적으로 유지한다.

상태 로그는 덧붙이기만 한다.

```text
node <skill-dir>/scripts/gate-check.mjs --scope api --log "leaf-1.2.1 verified"
```

덧붙이기만 하는 기록은 갱신이 사라지는 일을 줄이지만 `PLAN.md`의 현재 상태 필드를 대신하지는 않는다.

## 세션별 훅 상태

Stop 훅은 결정된 스코프와 현재 세션을 키로 진행 상태를 저장한다. 동시에 들어온 훅 호출은 상태 갱신을 하나씩 순서대로 처리한다. 게이트 파일이 완료되거나 사라지면 쓸모없어진 상태를 지운다. 한 세션이 다른 세션의 진행 없는 차단 6회를 대신 써 버릴 수 없다.

훅은 설치 스크립트의 `--scope`로 고정하거나, 다음 명령으로 기록된 세션 바인딩으로 스코프를 결정할 수 있다.

```text
node <skill-dir>/scripts/gate-check.mjs --scope api --bind <session-id>
```

저장된 세션 id를 비밀 값이나 신원 증명으로 취급하지 않는다.

## 알맞은 분리 수준 고르기

- 읽기 위주의 작업이나 소유권이 단순하게 겹치지 않는 리프에는 작업 트리 하나에 스코프 여러 개를 쓴다.
- 워크트리 안의 출력이나 생성 파일이 서로 충돌할 수 있으면 파이프라인마다 워크트리를 하나씩 쓴다. 캐시 쓰기가 충돌할 수 있으면 캐시 디렉터리를 따로 설정한다. 워크트리는 외부 캐시나 서비스를 분리하지 않는다.
- 신뢰할 수 없는 명령에는 운영체제나 컨테이너 수준의 분리를 쓴다. unlazy의 승인과 점유는 샌드박스가 아니다.

병렬 실행은 실제 경과 시간을 바꿀 뿐 증거 기준은 바꾸지 않는다. 부모 재검증과 중간 노드 통합은 여전히 필요하다.
