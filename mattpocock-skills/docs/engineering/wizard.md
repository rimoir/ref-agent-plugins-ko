## 하는 일

`wizard`는 사람이 손으로 해야 하는 절차를 한 단계씩 안내하는 대화형 bash 스크립트를 만든다. 외부 서비스를 연결하는 일, 한 번만 하는 마이그레이션을 실행하는 일, 프로젝트를 A 상태에서 B 상태로 옮기는 일이 그런 절차다. 스크립트는 각 URL을 열고, 무엇을 클릭하고 복사할지 알려 주고, 사람이 입력한 값을 받아 `.env` 파일과 GitHub Actions 시크릿에 쓴다.

스크립트는 [에이전트](https://www.aihero.dev/ai-coding-dictionary/agent)가 쓰지만 에이전트는 그 스크립트를 절대 실행하지 않는다. 실행은 사용자가 자기 컴퓨터에서 한다. 그래서 마법사(wizard)는 사람이 읽고 따라 하는 안내 목록이 아니다. 절차를 진행하고 진행 상태를 관리하는 프로그램이고, 사용자는 클릭하고, 붙여 넣고, Enter를 누르기만 하면 된다.

## 언제 쓰나

`/wizard`를 입력해서 실행할 수 있고, 에이전트가 스스로 실행할 수도 있다. 에이전트가 작업하다가 사람이 해야 하는 단계(에이전트가 직접 발급할 수 없는 키, 에이전트가 클릭할 수 없는 대시보드)를 만나면, 안내를 채팅에 써서 금방 위로 밀려나게 두지 않고 마법사를 만들어 준다.

다음 작업을 막고 있는 일이 대시보드를 돌아다니며 해야 하는 작업일 때 쓴다.

| 상황 | 마법사가 하는 일 |
| --- | --- |
| 새로 온 개발자가 앱을 띄우려면 서비스 여섯 개를 설정해야 한다 | 대시보드를 순서대로 열고, 키를 받아 `.env`와 CI에 쓴다 |
| 한 번만 하는 마이그레이션에서 정해진 순서대로 설정을 바꿔야 한다 | 되돌릴 수 없는 단계를 순서대로 놓고 각 단계 앞에서 확인을 받는다 |
| 프로젝트를 A 상태에서 B 상태로 한 번 옮겨야 한다 | 전환 과정을 안내하고, 하지 못한 일을 알려 준다 |
| 그 단계들을 README에 적으려던 참이다 | 대신 실행할 수 있는 버전을 만든다. 이 버전은 README처럼 낡아도 모른 채 지나가기 어렵다 |

무엇을 만들지 *정하는* 데는 쓰지 않는다. 그 일에는 [grill-with-docs](https://aihero.dev/skills-grill-with-docs)와 [to-spec](https://aihero.dev/skills-to-spec)을 쓴다.

## 사전 준비

마법사를 만드는 데 필요한 것은 없다. 만들어진 마법사는 bash에서 실행되고, GitHub 시크릿이나 변수를 설정하는 단계에서는 `gh`를 쓴다. `gh`가 없거나 인증되지 않았으면 실행이 실패하지 않는다. 그 단계는 경고로 바뀌고, 마지막 요약에서 손으로 설정해야 할 항목을 알려 준다.

## 단계

**단계**(stage)는 한 화면에서 하는 작업 하나다. 스크립트는 단계가 바뀔 때마다 터미널을 지우므로, 한 화면을 넘치는 단계는 위로 밀려난 부분을 잃는다. 단계는 의존 순서대로 작성하고 `TOTAL_STAGES`를 설정한다. 이 값으로 진행 상황을 표시한다.

범위는 스크립트를 한 줄이라도 쓰기 전에 정한다. 이 [스킬](https://www.aihero.dev/ai-coding-dictionary/skill)은 사용자에게 바로 묻지 않고 저장소부터 읽는다. `.env*`, `docker-compose*`, 프레임워크 설정, 그리고 `.github/workflows/` 안의 모든 `secrets.*` / `vars.*` 참조를 읽는다. 이 참조 하나하나가 마법사가 만들어야 할 값이다. 그런 다음 단계 목록을 순서대로 보여 주고 확인을 받는다. 확인을 받은 뒤에야 단계마다 사람이 따라갈 정확한 경로("Dashboard → Developers → API keys → Reveal test key → copy")를 정리한다. 현재 UI를 모르면 클릭 경로를 지어내지 않고 사용자에게 묻거나 문서를 확인한다.

범위를 정할 때 받아야 하는 값마다 어디에 쓸지도 정한다.

| 쓰는 곳 | 언제 |
| --- | --- |
| `.env`만 | 로컬 개발에는 필요하고 CI에는 필요 없다 |
| GitHub 시크릿 | CI가 읽고, 민감한 값이다 |
| GitHub 변수 | CI가 읽고, 공개 값이다 |
| `.env`와 시크릿 둘 다 | 로컬 개발과 CI 모두 필요하다 |
| 아무 데도 쓰지 않는다 | 동작만 하는 단계다. 설정을 바꾸거나 요금제를 올리는 단계가 그렇다 |

## UX는 템플릿에 이미 들어 있다

[템플릿](https://github.com/mattpocock/skills/blob/main/skills/engineering/wizard/template.sh)에 사용 경험 전체가 들어 있다. 남은 시간을 함께 보여 주는 진행 표시, 확인 절차, WSL을 포함한 여러 플랫폼에서 URL 열기, 시크릿 입력 숨기기, 여러 번 실행해도 결과가 같은 `.env` 갱신, `gh secret` / `gh variable` 쓰기, 그리고 건너뛰어야 했던 항목을 모두 보여 주는 마지막 요약이다. `STAGES` 표시 위쪽은 모두 고정된 라이브러리다. 모든 마법사에서 똑같고 절대 손으로 고치지 않는다. 모든 마법사가 똑같이 동작하는 것이 핵심이다. 할 일은 절차의 범위를 정하고 그 단계들을 작성하는 것뿐이다.

마법사를 쓰는 에이전트는 그 마법사를 처음부터 끝까지 실행하지 않는다. 마법사가 브라우저를 열고 사람의 입력을 기다리기 때문이다. 대신 정적으로 검증한다. `bash -n`을 실행하고, `shellcheck`가 있으면 그것도 실행하고, 모든 값이 범위를 정할 때 정한 자리에 쓰이는지, `set_secret`의 이름이 모두 CI의 실제 `secrets.*` 참조와 일치하는지 코드를 따라가며 확인한다. 그러니 첫 실행은 사용자가 하고, 그 실행이 곧 테스트라고 생각해 둔다.

## 기본적으로 일회용

| 상황 | 스크립트를 어떻게 할지 |
| --- | --- |
| 한 번만 하는 마이그레이션, 개인 설정, 다시 하지 않을 전환 | 임시 경로나 `scripts/` 경로에 저장하고, 실행하고, 지운다 |
| 이 저장소에 다음에 올 사람에게도 필요한 설정 경로 | 커밋하고 README에서 링크한다. 그러면 다음 사람은 에이전트에게 다시 묻지 않고 스크립트를 실행한다 |

## 자주 묻는 질문

**API 키가 모델의 컨텍스트에 들어가나요?**

아니다. 에이전트는 스크립트를 쓰기만 하고 실행하지 않는다. 스크립트는 사용자가 직접 실행하고, 그 스크립트가 키를 터미널에서 입력을 숨긴 채 받아 `.env`나 `gh secret`에 바로 쓴다. 마법사는 CLI이고 모델과 연결되어 있지 않다. 단, 이것은 마법사가 실행 중에 받는 값에만 해당한다. 절차의 범위를 정하는 동안 채팅에 키를 붙여 넣으면, 그 키는 붙여 넣은 다른 글과 마찬가지로 [컨텍스트](https://www.aihero.dev/ai-coding-dictionary/context)에 들어간다.

**잘못 입력한 값을 되돌아가서 고칠 수 있나요?**

실행 도중에는 안 된다. 뒤로 가기 버튼이 없다. 단계는 앞으로만 진행되고, 3단계에서 답을 잘못 입력했다면 Ctrl-C로 멈추고 다시 실행해야 한다. 다시 실행하는 부담은 일부러 작게 만들었다. `.env`에 이미 쓴 값은 기본값으로 다시 제시되므로, 제대로 입력한 단계는 Enter로 넘기고 틀린 값만 다시 입력하면 된다. 이 문제는 출시 주에 나왔고 그 뒤로 지금까지 해결되지 않았다. "정말 좋았어요! 그런데 하나만요, 입력한 걸 되돌아가서 고칠 방법이 있나요?"

관련된 버그도 아직 열려 있다. `ask` 프롬프트에서 화살표 키를 누르면 커서가 움직이지 않고 `^[[D` / `^[[C`가 입력된다. 프롬프트가 Readline이 아니라 `read -r`를 쓰기 때문이다([issue #741](https://github.com/mattpocock/skills/issues/741)). Backspace는 동작하고 화살표 키는 동작하지 않는다. 틀린 곳으로 커서를 옮기지 말고, 틀린 곳까지 지운 뒤 다시 입력한다.

**이미 설정해 둔 것을 알고 있나요?**

일부만 알고, 출시 때 사람들이 기대한 것보다는 적게 안다. 묻기 전에 저장소(`.env` 파일, `docker-compose`, 프레임워크 설정, CI의 `secrets.*` 참조)를 읽는다. 그래서 README처럼 처음부터 시작하지 않고 실제로 빠진 값만 범위에 넣는다. 외부 서비스 쪽은 확인하지 않는다. `.env`에 이미 키가 있으면 마법사가 그 값을 다시 제시하고, Enter를 누르면 그대로 유지된다. Stripe 계정은 이미 만들었지만 키를 저장해 두지 않았다면, 마법사는 그 키를 받으러 여전히 대시보드로 안내한다.

**작업 흐름에서 어디에 들어가나요? 집요한 질문과 스펙 다음인가요?**

정해진 자리는 없다. 흐름 속 한 단계가 아니라 단독 스킬이다. 흔히 `/grill-with-docs → /to-spec → /wizard` 순서라고 짐작하고, 그 순서도 괜찮다. 하지만 이 스킬을 쓰게 되는 계기는 손으로 해야 하는 절차가 나타나는 것이고, 그런 일은 언제든 생긴다. 시작하기 전일 수도, 구현 도중일 수도, 출시하고 한참 뒤일 수도 있다. 이 스킬은 미리 알아보는 도구로도 쓸 수 있다. 범위를 정하는 동안 작업에 숨어 있던 사전 조건, 예를 들어 생각하지 못했던 API 키 세 개가 드러나므로, 작업을 시작하기로 정하기 전에 그것을 알 수 있다.

**Claude Code 밖에서도 동작하나요?**

만들어진 산출물은 조건 없이 동작한다. 평범한 bash 스크립트이고, 어떤 [하네스](https://www.aihero.dev/ai-coding-dictionary/harness)가 만들었는지 상관하지 않는다. 스킬 자체는 모델 호출 스킬(모델이 스스로 실행할 수도, 사람이 입력해 실행할 수도 있는 스킬)이라 어디서나 목록에 나온다. Claude Code에서는 `/wizard`, Codex에서는 `$wizard`를 입력하거나, 막혀 있는 설정 작업을 설명하기만 하면 된다. 모델 호출 스킬이라서 [#693](https://github.com/mattpocock/skills/issues/693)의 영향도 받지 않는다. 이 이슈에서 Claude 데스크톱과 웹은 *사용자 호출* 스킬(사람이 이름을 입력해야만 실행되는 스킬)을 [모델](https://www.aihero.dev/ai-coding-dictionary/model)에게 보여 주는 목록에서 빼고, 설치되지 않았다고 보고한다.

**예전에는 사용자 호출 스킬이지 않았나요?**

그랬다. 지금은 모델 호출 스킬이라서, 에이전트가 사람이 해야 하는 단계를 만나면 요청하지 않아도 이 스킬을 쓴다. 전에 할 수 있던 일은 모두 그대로 된다. 모델 호출은 에이전트가 이 스킬을 쓸 수 있게 *더해 줄* 뿐이고 사용자가 호출하는 방법을 없애지 않는다. 그래서 `/wizard`는 전과 똑같이 동작한다. 달라진 것은 이 변경으로 사라지는 실패 방식이다. 에이전트가 구현 도중 자격 증명이 없어 더 진행하지 못하게 되면, 채팅에 번호 붙은 단계 여섯 개를 한꺼번에 적어 놓고 사용자에게 손으로 따라 하게 하던 일이다.

**예전에는 `in-progress/`에 있었는데 지금은 어디 있나요?**

v1.2부터 `engineering/`에 있다. 베타 버킷에서 나와 이제 플러그인에 포함되므로, 따로 설치하지 않아도 정식 버킷(promoted, 플러그인에 포함되고 문서 페이지가 있는 engineering/과 productivity/)의 다른 스킬과 함께 설치된다. 정식 버킷으로 옮기면서 동작은 바뀌지 않았다.

## 잘 동작하고 있다는 신호

- 스크립트가 만들어지기 전에 순서대로 놓인 단계 목록과 각 단계가 만드는 값을 보여 주고 확인을 받는다.
- 어떤 값을 묻기 전에 그 값이 있는 페이지의 URL을 먼저 연다. 가져오라고 안내받지 않은 값을 붙여 넣으라는 요청은 받지 않는다.
- 시크릿은 화면에 보이지 않게 입력한다. 민감한 값이 터미널 기록에 남지 않는다.
- 각 단계가 한 화면에 들어간다. 아직 봐야 할 내용이 위로 밀려나지 않는다.
- Ctrl-C로 멈추고 다시 실행하면, 이미 저장한 값을 기본값으로 제시하며 멈춘 곳부터 이어 간다.
- 마지막 화면에 쓴 값의 목록이 나오고, 하지 못해서 사용자가 손으로 마무리해야 하는 일의 목록이 따로 나온다.

## 전체 흐름에서의 위치

`wizard`는 언제든 꺼내 쓰는 단독 스킬이고, 자동화가 멈추고 사람이 클릭해야 하는 지점에서 쓴다. 가장 가까운 관련 스킬은 [setup-matt-pocock-skills](https://aihero.dev/skills-setup-matt-pocock-skills)다. 둘 다 저장소를 작업할 수 있는 상태로 만드는 스킬이다. setup-matt-pocock-skills는 이 스킬 모음을 설정하고, `wizard`는 그 밖의 모든 것을 설정하는 경로를 만든다. [implement](https://aihero.dev/skills-implement)와도 함께 쓴다. 구현한 기능에 자격 증명이나 손으로 하는 전환 작업이 필요하면, 사람이 맡을 부분은 마법사로 처리한다. 지금 어떤 스킬이 맞는지 모르겠으면 [ask-matt](https://aihero.dev/skills-ask-matt)가 알려 준다.
