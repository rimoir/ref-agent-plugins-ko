# 스킬 작성 방식

[`writing-for-agents`](SKILL.md)에서 스킬에만 해당하는 부분이다. 문서가 스킬일 때 달라지는 점(frontmatter, 호출 방식 선택, 안내 스킬(router, 다른 스킬과 각각 쓸 때를 알려 주는 스킬))을 다룬다. 그 밖의 작성 방법은 모두 `SKILL.md`의 공통 참고 자료를 따른다.

## 호출 방식

선택지는 다음과 같고, 어느 쪽을 고르느냐에 따라 컨텍스트 부하와 인지 부하 중 어느 쪽을 치를지가 정해진다.

- **모델 호출** 스킬(모델이 스스로 실행할 수도, 사람이 입력해 실행할 수도 있는 스킬)은 `description`을 유지하므로 에이전트가 스스로 실행할 수 있고 다른 스킬도 호출할 수 있다. 사람이 이름을 입력해 실행할 수도 있다. 모델 호출은 항상 사용자 호출을 _포함한다_. description은 에이전트가 찾아 쓰는 경로를 더할 뿐 사람이 호출하는 경로를 없애지 않는다. description은 스킬의 가장 위에 있는 컨텍스트 포인터이고 항상 로드되어 있어야 한다. 에이전트가 찾아 쓸 수 있는 대가로 영구적인 컨텍스트 부하를 치른다. 내용이 모두 참고 자료인 모델 호출 스킬은 공유 참고 자료를 두는 곳으로도 쓸 수 있다. 다른 스킬이 이 스킬을 호출할 수 있으므로 여러 스킬이 쓰는 참고 자료를 한곳에 둘 수 있다. 설정 방법: `disable-model-invocation`을 빼고, 트리거 분기를 담은 모델용 description을 쓴다(`SKILL.md`의 포인터 작성 규칙을 그대로 적용한다).
- **사용자 호출** 스킬(사람이 이름을 입력해야만 실행되는 스킬)은 에이전트가 description을 볼 수 없게 한다. 사람이 이름을 입력해야만 호출할 수 있고 다른 스킬은 호출할 수 없다. 컨텍스트 부하는 없지만 인지 부하를 치른다. 이 스킬이 있다는 것을 사람이 기억해야 한다. 설정 방법: `disable-model-invocation: true`를 설정한다. 그러면 `description`은 사람이 읽는 문구가 되므로 한 줄 요약으로 쓰고 트리거 목록은 뺀다.

에이전트가 스스로 이 스킬을 호출해야 하거나 다른 스킬이 호출해야 할 때만 모델 호출을 고른다. 사람이 직접 입력해서만 실행한다면 사용자 호출로 만들어 컨텍스트 부하를 치르지 않는다.

사용자 호출 스킬 둘이 함께 쓰는 참고 자료는 어느 쪽에도 둘 수 없다. description이 없어서 한쪽이 다른 쪽을 호출할 수 없기 때문이다. 이런 자료는 스킬 체계 밖의 일반 파일로 뺀다. 그러면 어떤 스킬이든 가리킬 수 있는 외부 참고 자료가 된다.

## 호출 방식에 따라 나누기

나누기 기준 중 호출 방식에 따른 기준이다(순서에 따른 기준은 `SKILL.md`에 있다). 그 스킬을 단독으로 트리거해야 하는 별개의 핵심 단어가 있을 때(실제로 프롬프트에서 쓰는 트리거 단어), 또는 다른 스킬이 호출해야 할 때 모델 호출 스킬을 따로 떼어 낸다. 새로 항상 로드되는 description만큼 컨텍스트 부하를 치르므로, 독립적으로 호출할 수 있다는 점이 그만한 가치가 있어야 한다.

## 안내 스킬

사용자 호출 스킬이 기억할 수 없을 만큼 많아지면, 그만큼 쌓인 인지 부하는 **안내 스킬**로 해결한다. 안내 스킬은 다른 스킬들의 이름과 각각 언제 쓰는지를 알려 주는 사용자 호출 스킬 하나로, 사람은 여러 스킬 대신 이 스킬 하나만 기억하면 된다. 안내 스킬은 다른 스킬을 알려 줄 수만 있고 실행할 수는 없다. 사용자 호출 스킬에는 description이 없어서 사람 말고는 아무도 호출할 수 없기 때문이다.
