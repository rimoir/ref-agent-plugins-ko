### Runtime forensics

**진단은 내가 맡는다. 소스로 이론을 세우지 말고 살아 있는 프로세스를 계측한다.** 산출물은 수정이 아니라 근거를 단 진단이다.

1. 제어 스킬로 맞는 표면에서 살아 있는 신호를 잡는다. 계속 도는 프로세스에는 CPU 프로파일, 누수에는 힙 스냅숏, 화면 결함에는 CDP trace. 추측이 아니라 실제 산출물이다.
2. 산출물을 결정적 증거로 줄인다. 핫 패스 위의 함수, 누수된 객체에서 GC 루트까지의 retainer 사슬, 입력 없이 도는 루프. 큰 산출물은 subagent에서 파싱하고(**guard-the-context-window** principle 스킬), 줄인 결과만 메인 스레드에 둔다. 각 subagent의 추론 수준은 Subagents 절에 따라 작업에 맞게 고른다.
3. 믿기 전에 메커니즘을 증명한다. 실행 중인 프로세스에 CDP eval로 계측을 주입하거나, 다시 불러오지 않고 실행 중인 코드를 핫픽스해서 가설을 싸게 확인한다.
4. 결과를 소스에 대응시킨다. 파일, 심볼, 할당하거나 예약하는 줄.
5. 처리량 체크포인트는 한 줄로 둔다. `throughput checkpoint: n/a, read-only forensics`.

**답변:** 잡은 신호, 줄인 결과, 메커니즘을 증명한 방법, 소스 위치, 산출물 경로. 요청이 없으면 수정하지 않는다. 원인이 밝혀지면 Bug fix나 Perf로 넘긴다.
