# 숫자를 설명하라(Explain the Number)

- **"왜 두 배가 아닌가?"를 묻는다.** 결과를 묶어 두는 자원이나 코드 경로를 짚는다. 코어 하나, 락, 디스크, 네트워크, 부하 생성기 자체 같은 것이다. 실행 중에 뜬 프로파일이나 시스템 카운터에서 찾고, 그다음 소스와 연결한다. 코드를 읽고 한 추측은 제한 요인이 아니다. 숫자가 왜 두 배로 좋지 않은지 말할 수 없다면 무엇을 쟀는지 모르는 것이다.
- **숫자가 그 밖에 무엇을 재고 있을 수 있는지 나열하고, 하나씩 증거로 배제한다.** 흔한 용의자는 오류, 건너뛰었거나 캐시된 작업, 아예 돌지 않은 코드, 튜닝하지 않은 한쪽(기본 설정으로 둔 한쪽), 잡음, 종단 간으로 보면 의미 없을 만큼 작은 조각이다.
- **증거를 숫자 곁에 둔다.** 실행 횟수, 편차, 제한 요인을 노트나 연결된 산출물에 남긴다.

성능 숫자라면 [benchmark-checklist](../benchmark-checklist/SKILL.md) 스킬로 전체 절차를 밟는다. eval 결과라면 시행에 같은 질문을 던진다. 모든 실행이 과제를 해냈는가, 차이가 시행과 모델을 넘어 유지되는가, 그 시나리오가 중요한가.

숫자 뒤의 증거에 실행 횟수도, 편차도, 이름 붙은 제한 요인도 없다면, 또는 아낀 시간이 바꾼 조각이 원래 걸린 시간보다 크다면 이 원칙을 건너뛴 것이다.

[동작을 증명하라(Prove It Works)](../principle-prove-it-works/SKILL.md)와 다르다. 그쪽은 산출물이 진짜인지 확인한다.
