# 더하기 전에 빼기

시스템을 발전시킬 때는 먼저 복잡도를 덜어 내고, 그다음에 쌓는다. 기본값은 빼기다.

단순화를 꾸준한 투자로 삼는다. 처음 봤을 때와 같거나 더 작은 표면 뒤에, 설계를 조금 더 단순하고 더 유능하게 남겨 두고 떠난다.

- 만들기 전에 지우는 순서로
- 다듬기 전에 자르기(품질에 투자하기 전에 최소한까지 줄인다)
- 추측한 경계 사례가 아니라 관찰한 사용 방식에 맞춰 설계
- 명세가 요구하는 것 이상의 추측성 검증기, 파서, 가드 금지
- 프롬프트 단순화(중복 지시, 과한 템플릿 제거)
- 새로운 내용이 없는 참조는 스텁으로 남기지 말고 삭제
