사용자가 스펙이나 티켓에 적은 작업을 구현한다.

사용자가 티켓 참조를 넘기면 이슈 트래커에서 가져와 시작하기 전에 제목을 말한다. 참조가 모호하면 묻는다.

가능하면 미리 합의한 교체 지점(seam, 그 자리의 코드를 고치지 않고 동작을 바꿔 끼울 수 있는 위치이자 모듈 인터페이스가 놓이는 곳)에서 Skill 도구로 "tdd"를 호출한다.

타입 검사와 단일 테스트 파일 실행은 자주 하고, 전체 테스트 스위트는 마지막에 한 번 실행한다.

작업이 끝나면 Skill 도구로 "code-review"를 호출해 작업을 리뷰한다.

작업을 현재 브랜치에 커밋한다.
