# 검증 가능한 단위로 작업 나누기(Sequence work into verifiable units)

작업을 작은 단위의 연속으로 배열하고, 각 단위는 확인할 수 있는 상태로 끝내며, 현재 단위가 green이 되기 전에는 나아가지 않는다.

**이유:** 원인이 된 단위에서 잡은 고장은 위치를 찾기 싸다. 한 묶음이 끝난 뒤 잡은 고장은 파묻혀 있고, 이미 망가진 기반 위에 더 쌓아 버린 뒤다. 같은 단위를 리뷰어가 재생할 수 있는 전달 순서로 배열하면 "날 믿어"가 "red가 됐다가 green이 되는 걸 봐"로 바뀐다.

**실행.** 일괄 수정, 마이그레이션, 비슷한 수정의 연속에서는 다음을 시작하기 전에 각 변경을 검증한다. 각 단위는 전후로 묶인 괄호다. 정상으로 알려진 상태, 변경 하나, 확인 실행, 그다음 진행이다. 모든 확인이 실제 기준선과 비교되도록 먼저 깨끗한 trunk에 rebase한다. 지렛대(lever)가 수정을 할 때는 단위별 확인 비용이 거의 없다. 그래도 돌린다.

**전달.** 커밋과 PR은 작업을 증명하는 순서로 쌓는다. 정석은 실패하는 테스트가 먼저, 그 위에 수정이다. 다른 서사 순서로는 형태를 바꾸기 전의 빼기, 처치 전의 기준선 확보, 기능 전의 비계가 있다. 각 커밋은 홀로 착지할 수 있고, 순서 전체가 하나의 논증으로 읽힌다.

각 확인을 진짜로 유지하는 **prove-it-works** 원칙 스킬, 단위별 확인을 싸게 만드는 **build-the-lever** 원칙 스킬과 짝을 이루는 순서 측면의 보완이다.
