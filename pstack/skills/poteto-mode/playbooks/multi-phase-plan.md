### 다단계 또는 다중 PR 계획

**너는 코드가 아니라 계획을 맡는다. 계획은 owner가 칸 하나씩 실행하고 운영자(operator)가 증거로 감사하는 체크리스트다.** 산출물은 계획이다. 구현하지 않는다.

1. 변경이 파일 한두 개이고 접근법이 뻔하면 계획을 건너뛴다. 그렇다고 말하고 멈춘다.
2. 쓰기 전에 `playbooks/prototype.md`에 따라 열린 질문을 프로토타입으로 정리한다. 어떤 실행으로도 정할 수 없는 제품 판단이나 취향 문제만 운영자에게 묻는다.
3. 계획 파일을 쓴다. 무엇이 바뀌는지, 착지 순서대로 늘어놓은 PR id, 의존 그래프로 시작한다. 의존 그래프에는 어떤 PR이 독립적이라 trunk에서 갈라지는지, 어떤 PR이 어떤 PR을 기다리는지, 각 PR이 건드려도 되는 파일을 적는다. 그다음 PR 하나에 섹션 하나를 쓴다. PR 하나는 자체 증거를 갖춘 변경 하나다(**sequence-verifiable-units** 원칙 스킬). 섹션마다 의존하는 것, 수정하는 파일, 만드는 변경 하나, 눈에 보이는 결과, 검증을 체크박스로 둔다.
4. 테스트만으로는 검증이 충분하지 않다. PR은 unit, live, perf 칸이 모두 체크되어야만 검증된 것이다. live 칸은 각각 구체적인 시나리오와 통과 조건으로 실제 화면을 조작한다. perf 칸에는 지표, 측정(probe), 먼저 잰 trunk 기준선, 실패로 판정하는 수치를 적는다. 상호작용을 바꾸는 PR은 머지 전에 운영자의 리뷰를 기다린다.
5. 계획 경로를 넘겨주고 멈춘다. 실행은 운영자가 명시적으로 진행하라고 할 때 시작한다.

**답변:** 계획 경로, 의존 관계와 리뷰 게이트 대상을 포함한 PR id 목록, 증명되지 않은 채 남은 것.
