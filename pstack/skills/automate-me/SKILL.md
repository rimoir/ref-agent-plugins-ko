# Automate me

사용자의 작업 관례를 에이전트가 따를 스킬로 바꾸는 안내형 흐름이다. 결과물은 사용자에게 맞춘 `-mode` 스킬 하나다(예: `jay-mode`, `priya-mode`).

이 스킬은 다른 셋을 조율한다. 인라인 채굴 단계(1단계 참고), Cursor 내장 `create-skill`(작성), **unslop** 스킬(문장 규율)이다. 이 스킬은 그것들의 순서를 잡을 뿐 대신하지 않는다.

## 흐름

### 0. 기존 스킬 확인

사용자 핸들에 맞는 `.cursor/skills/**/*-mode/SKILL.md`와 `~/.cursor/skills/*-mode/SKILL.md`를 재귀적으로 찾는다. mode 스킬은 최상위뿐 아니라 개인 카테고리 디렉터리(`.cursor/skills/<handle>/`)에 있을 수도 있다. 하나라도 있으면 `AskQuestion`으로 의도를 확인한다(사용자가 이미 "update my skill" 같은 말을 했다면 생략한다).

- 기존 스킬 갱신(반복 실행의 기본값)
- 새로 시작(드물다, 하기 전에 이유를 묻는다)

갱신 모드는 나머지 흐름을 바꾼다.
- 1단계는 스킬을 마지막으로 수정한 이후의 이력만 채굴한다(`git log -1 --format=%cI <path>`).
- 2단계는 처음부터 무엇을 담을지가 아니라 무엇이 바뀌었거나 빠졌는지 묻는다.
- 4단계는 기존 파일을 제자리에서 고친다. 사용자가 반박하지 않은 절은 보존한다. 새 증거가 있는 절은 고친다. 정말로 새로운 규칙일 때만 절을 추가한다.

### 1. 이력 채굴

확산하기 전에 활성 워크스페이스의 트랜스크립트 위치를 찾는다. 시스템 프롬프트에 워크스페이스의 `agent-transcripts/` 디렉터리가 나온다. 그 경로만 쓴다. `~/.cursor/projects/*/`를 glob으로 훑지 않는다. 그러면 워크스페이스 경계를 넘어 무관한 프로젝트의 비공개 대화를 읽게 된다.

그 범위 안에서 최근 에이전트 대화를 살펴 반복되는 패턴을 찾는다. 이력을 여러 조각으로 나눠 subagent 여러 개를 병렬로 돌린다(예: 최근 2~4주를 조각 3개로 나눠 각 조각에 재료가 충분하게 한다). 각 subagent의 추론 수준과 속도(fast 또는 표준)는 **poteto-mode** 스킬의 Subagents 절에 따라 작업에 맞게 고른다. 조각을 맡은 각 채굴 subagent는 부모가 넘긴 워크스페이스 범위 경로에서 트랜스크립트를 읽고, 아래 신호를 찾고, 본 패턴을 증거 포인터와 함께 짧은 구조화 목록으로 돌려준다. 기본으로 찾아볼 신호는 다음과 같다.

- 응답 선호(길이, 어조, 형식, "더 쉽게 설명해" 같은 교정)
- 위임 습관(subagent, 모델, 특화 워크플로, 병렬성)
- 검증 태도("완료"의 의미, 단위 테스트 대 실제 재현, 리뷰어)
- 코드와 문장 규율(스타일, 인용하는 원칙, lint/format 도구)
- 절차 관례(worktree, 커밋, PR, 리뷰·머지 도구)
- 메타 선호(작업 중 스킬 고치기, 새 스킬 제안하기)

신호를 격상하기 전에 조각끼리 교차 확인한다. 두 조각 이상에서 보인 패턴은 신뢰도가 높다. 한 번만 나온 신호는 약하며 보통 버린다.

### 2. 사용자에게 직접 묻기

채굴로는 아직 드러나지 않은 의도를 놓친다. 사용자에게 처음부터 타이핑하게 하지 말고 `AskQuestion` 도구(구조화된 객관식)를 쓴다.

형태는 질문 한두 개에 선택지 4~6개씩이며, 카테고리 질문에는 `allow_multiple: true`를 쓴다. 넓게 시작하고("어떤 영역이 가장 중요한가?"), 고른 영역에 대해 구체적 선택지로 이어 묻는다. 구조화된 질문이 끝나면 선택지가 놓친 것을 잡도록 자유 형식 채팅 질문을 하나 던진다.

질문 20개를 쏟아 내지 않는다.

### 3. 발견 묶기

합친 신호를 절로 묶는다. 흔한 절은 다음과 같다(해당하는 것만 쓴다).

- **응답 스타일**: 길이, 어조, 형식.
- **자율성**: 묻지 않고 어디까지 할지, MCP 도구 사용.
- **먼저 이해하기**: 변경 범위를 잡거나 조사할 때 꺼낼 스킬.
- **Subagent**: 기본값, 병렬성, 과제별 모델, 특화 워크플로.
- **문장 / 코드 규율**: 원칙, lint 도구, 스타일 가이드.
- **리뷰와 검증**: 재현 태도, 검증 스킬, 실사용 테스트 도구.
- **절차**: git worktree, 커밋, PR, 리뷰·머지 도구.
- **스킬**: 스킬 작성 습관, 스킬부터 고치기, 새 스킬 제안.

형태는 **poteto-mode** 스킬을 보면 된다. 세밀함의 정도를 보려고 읽는다. 내용은 베끼지 않는다. 사용자의 규칙은 poteto-mode의 규칙과 같지 않다.

### 4. 스킬 초안

Cursor 내장 `create-skill` 스킬로 스킬을 작성한다. 배치는 다음과 같다.

- 경로: 기존 mode 스킬이 있으면 그 카테고리를 유지한다. 새 mode라면, 레포에 그 핸들의 개인 카테고리가 이미 자리 잡았을 때 `.cursor/skills/<handle>/<handle>-mode/SKILL.md`를 쓴다. 그렇지 않으면 프로젝트의 `.cursor/skills/<handle>-mode/SKILL.md`가 기본이다(사용자가 개인 스킬을 원하면 `~/.cursor/skills/<handle>-mode/`).
- 핸들: 사용자의 이름이나 사용자가 정한 식별자.
- frontmatter `description`: "write code"나 "review PR" 같은 일반 키워드가 아니라 사용자 이름, `/<handle>-mode`, "그 사람 스타일로 작업"에 걸리게 한다.
- frontmatter 서식: `create-skill`의 YAML 규칙을 따른다. `description`은 YAML 스칼라 하나로 유지한다. 구두점이나 줄바꿈 때문에 필요하면 따옴표로 감싸거나, `description: >-`에 들여쓴 이어지는 줄을 쓴다.
- frontmatter `disable-model-invocation: true`가 기본이다. 사용자가 매 턴 자기 mode가 적용되길 명시적으로 원할 때만 끈다.

### 5. 문장 다듬기

모든 줄에 **unslop** 스킬과 `create-skill`의 작성 지침을 적용한다.

초안을 사용자에게 보여 주고 피드백을 받는다. 여러 번 반복할 것을 예상한다. 가차 없이 줄인다. mode 스킬은 매뉴얼이 아니다.

### 6. 착지

main에서 갈라진 worktree에서 작업한다. 커밋하고 PR을 연다. main에 직접 push하지 않는다.

## 안전장치

- **대화 하나에 과적합하지 않는다.** 한 번 말했다가 다른 때 뒤집은 선호는 잡음이다. 규칙으로 굳히기 전에 여러 사례를 요구한다.
- **재주 부리지 않는다.** 다른 스킬 내용을 되풀이하거나, 비유를 지어내거나, 에이전트 독자에게 "시적인" 문장을 쓰는 것은 이득 없는 비용이다. 실무적으로 쓴다.
- **인라인하지 말고 참조한다.** 사용자가 의존하는 다른 스킬은 발췌를 붙여 넣지 말고 경로 참조로 남긴다. 사용자가 다른 곳에서 관리하는 원칙 문서도 마찬가지다.
- **절은 최소로.** 사용자가 그 영역에 기본값이 아닌 구체적 규칙을 가졌을 때만 절을 더한다. "명확하게 소통한다"는 절이 아니다. "문단은 짧게. 선택지를 비교할 때는 표. 항목이 정말 병렬일 때만 글머리표."는 절이다.
- **관례 이름은 일반적으로.** 명령문에는 작성자 이름 대신 "사용자"나 "사람"을 쓴다.
- **대칭을 억지로 맞추지 않는다.** 적어 둘 만한 절차 규칙이 없는 사용자라면 절차 절을 통째로 건너뛴다.

## 평가

`-mode` 스킬은 주관적인 산출물이다. `create-skill` 방식의 테스트·반복 벤치마크 루프는 여기서 쓸모가 없다. 사용자와 감으로 확인한다. 그 사람처럼 읽히는가? 놓친 것은 없는가? 그러고 나서 내보낸다.

description 최적화 루프는 실제로 스킬의 트리거 정확도가 문제로 드러날 때만 돌린다.

## 쓰지 않을 때

- 사용자가 작업 관례가 아니라 특정 과제용 스킬을 원한다: `create-skill`만 쓰고 채굴은 필요 없다.
- 사용자가 좁은 워크플로 하나를 담고 싶어 한다(예: "커밋 메시지 쓰는 방식"). 그것은 mode 스킬이 아니라 일반 스킬이다.
