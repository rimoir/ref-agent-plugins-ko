# 기여하기

unlazy를 개선해 주어 고맙다. 변경은 한 가지에 집중하고, 테스트할 수 있고, 여러 플랫폼에서 동작해야 하며, 근거로 내세우는 증거를 정직하게 밝혀야 한다.

## 환영하는 변경

- 파서, 검사기, 훅, 설치 스크립트, 동시 실행, 이식성 수정
- 게이트(완료로 인정하려면 충족해야 하는 조건 한 항목) 작성이나 오케스트레이션(총괄 에이전트가 작업을 여러 에이전트에 나눠 맡기고 검증과 통합을 하는 방식) 지침을 더 명확하게 다듬는 변경
- 보고된 동작을 확인하는 회귀 테스트
- 범위를 좁혀 쓴 주장을 직접 뒷받침하는 최근 연구
- `SKILL.md`를 읽어 들이는 에이전트를 위한 호환성 수정

## 기본 규칙

- **강제는 구조적 장치로 한다.** 완료 여부는 유효한 게이트 파일, 최신 증거, 부모 재검증(`--reverify`), 통합 검사로 판정한다.
- **형식을 하나의 계약으로 다룬다.** 게이트 파일 형식을 바꾸면 공유 파서, 검사기, 훅, 템플릿, 참조 문서, 테스트를 함께 고쳐야 한다.
- **형식이 잘못된 완료 상태는 실패로 처리한다(fail closed).** 유효하지 않은 입력이 `ALL MET`이 되거나 Stop 훅에서 아무 말 없이 허용되면 안 된다. 단 문서에 적힌 보안 경계가 진단 메시지를 붙인 허용을 요구하는 경우는 예외다.
- **`CHECK:`를 코드로 다룬다.** 명시적 승인, 승인 무효화, 명령을 실행하지 않는 상태 조회 동작을 유지한다. 편의를 위해 신뢰 경계를 약하게 만들지 마라.
- **Node 16 호환성을 유지하고 런타임 의존성을 두지 않는다.** 지원하는 최저 버전에서 쓸 수 있는 Node 표준 라이브러리 API를 쓴다. 셸, 경로, 줄바꿈, 파일 잠금, 설치 스크립트 코드를 바꿀 때는 Windows, macOS, Linux에서 동작을 테스트한다.
- **주장을 정확하게 쓴다.** 가능하면 1차 연구나 공식 플랫폼 문서를 근거로 쓴다. 체크포인트 지표와 엔드투엔드 성공, 전체 적합도와 부분 집합 적합도, 탐색적 관찰과 재현 가능한 결과를 구분한다.
- **스킬 메타데이터를 유효하게 유지한다.** `SKILL.md` frontmatter에는 `name`과, 트리거 문구를 충분히 담은 3인칭 `description`만 넣는다. `agents/openai.yaml`을 이와 맞게 유지하고, 실제 파일이 없으면 아이콘 경로를 추가하지 마라.
- **스킬 본문은 명령형으로 쓰고 점진적 공개(progressive disclosure) 방식을 따른다.** 핵심 워크플로는 `SKILL.md`에 두고, 자세한 계약은 직접 링크한 참조 문서에 둔다.
- **em dash와 en dash를 쓰지 않는다.** 하이픈, 콜론, 문장 나누기를 쓴다.
- **관련 없는 사용자 설정을 보존한다.** 설치 스크립트를 바꿀 때는 설정의 컨테이너 형태를 검증하고, 원자적으로 갱신하고, unlazy 자신의 핸들러만 제거해야 한다.

## 테스트

의존성을 설치하지 않는다. 다음을 실행한다.

```text
npm test
```

스크립트를 바꾸면 수정 전에는 실패하는 회귀 테스트를 추가한다. 다음을 포함해 관련된 적대적 경계 조건을 다룬다.

- 옵션 순서를 바꿔 가며 파일 하나나 여러 파일을 명시적으로 지정하는 경우
- 상태 조회와 재검증의 구분, 판정 기준(oracle)이 바뀌었을 때의 무효화
- 게이트 0개, 중복, 불완전한 속성, 코드 펜스, 들여쓰기, CRLF, 포기 사유
- 검사기, 부모, Stop 훅 모두에서 포기를 성공이 아닌 인계로 다루는 것, 길이가 제한된 호스트 메시지
- 종료 코드 `0`과 `EXPECT:`를 함께 요구하는 조건, 타임아웃, 없는 명령, 출력 한도, 증거 삽입
- 저장소 밖에 있는 승인 저장소, 그리고 게이트 파일, 게이트, 명령, 기대 문자열, 작업 디렉터리, 셸, 타임아웃, 한도, 플랫폼, `PATH`에 승인을 묶는 바인딩
- 플랫폼별 기본 셸, 명시적 셸 지정, 물려받은 PATH, 공백이 들어간 경로
- Windows 프로세스 트리 정리의 성공, 도우미 실패, 직계 자식 프로세스 종료로 대체하는 방식, 타임아웃 후 최종 상태에 이르는 것
- 순차 실행 기본값과, 결정적이고 상한이 있는 `--jobs`
- 서로 충돌하는 점유(lease) 신청(`--claim`)이 동시에 들어오는 경우, 보수적인 glob 겹침 판정, 안전하지 않은 경로, 알 수 없는 리프(leaf, 트리 맨 아래의 작업 단위), 해제(`--release`)
- 게이트 동시 갱신과 세션별 훅 상태의 동시 갱신
- 네이티브 배정(dispatch)의 open/start/seal/return, 일부만 시작된 실행의 포기, 의미 기준의 진행 해시 계산
- PLAN 계약 누락, 최신이 아닌 담당과 확인 수단, 변경 사항, 명시적 제거, 범위를 좁힌 단독 경로
- Stop 훅 차단, 진행이 있을 때 차단 횟수 초기화, 여섯 번 차단 후 차단 해제, 모두 충족됐을 때의 정리, 모호한 경우, 세션 라우팅
- 설치 스크립트의 설치, 멱등성, 옮겨진 경로, 대상 형태가 맞지 않을 때의 거부, 관련 없는 핸들러 보존, 제거

최종 검증에서 문법 검사와 스킬 검증기를 함께 실행한다. 테스트는 결정적으로 유지하고 실제 사용자 설정과 분리한다.

## 문서 변경

동작에 관한 주장에는 정확한 출처를 링크하고 그 출처가 뒷받침하는 내용만 적는다. README의 출처 목록은 최신 공개 버전이나 발행일 순서로 정렬해 둔다. 날짜가 없는 출처는 추측하지 말고 날짜가 없다고 표시한다.

재현에 필요한 결과물과 계산 스크립트 없이 새 벤치마크 비율을 추가하지 마라. [research/validation-protocol.md](research/validation-protocol.md)를 따른다.

## 풀 리퀘스트

어떤 실패가 있었는지, 변경 후의 계약이 무엇인지, 정확한 회귀 증거가 무엇인지 설명한다. 관련 없는 리팩터링은 패치에 넣지 않는다. 사용자에게 보이는 동작이 바뀌면 `CHANGELOG.md`의 아직 릴리스하지 않은 대상 버전 항목(Unreleased) 아래를 갱신한다.
