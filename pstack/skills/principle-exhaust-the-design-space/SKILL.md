# 설계 공간을 다 뒤진다

새로운 상호작용이나 아키텍처 결정에 확립된 선례가 없으면 구현 전에 구체적인 대안 여러 개를 탐색한다. 잘못된 것을 만드는 비용이 선택지 세 개를 탐색하는 비용보다 크다.

**규칙.** 정답이 뻔하지 않으면 경쟁하는 프로토타입이나 스케치 2~3개를 만든다. 나란히 비교한다. 그다음에야 확정한다. "두 번 설계하라(Design it twice)"는 이 규칙의 다른 이름이다. 첫 모양을 살짝 바꾼 두 번째 버전은 치지 않는다.

**적용할 때:**
- 새로운 UI 상호작용(코드베이스에 선행 사례가 없음)
- 실행 가능한 접근법이 여러 개인 아키텍처 선택
- 사용자 경험이 논리가 아니라 느낌에 좌우되는 제품 설계 결정

**적용하지 않을 때:**
- 패턴이 확립된 기계적인 구현
- 목표 상태가 분명한 버그 수정이나 리팩터링
- 제약 때문에 실행 가능한 접근법이 하나뿐인 변경
