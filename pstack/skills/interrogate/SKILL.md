# Interrogate

설정된 모델마다 리뷰어 하나씩 띄워 코드 변경을 적대적으로 리뷰한다. 적대적 신호는 배정된 페르소나가 아니라 모델의 다양성에서 나온다. 산출물은 종합된 판정이다. 변경을 자동으로 적용하지 않는다.

## 1단계, 범위

맥락에서 리뷰할 대상을 찾는다.

- 사용자가 특정 파일이나 diff를 가리키면 그것을 쓴다.
- feature 브랜치에 있다면 `git diff main...HEAD`(또는 알맞은 base 브랜치)를 돌려 전체 변경을 얻는다.
- 사용자 메시지가 최근 작업을 언급하면 관련 파일을 모은다.

diff나 파일 내용과 함께, 리뷰어가 코드를 이해하는 데 필요한 주변 맥락 파일을 묶는다.

## 2단계, 의도

리뷰어를 띄우기 전에 사용자 메시지, 커밋 메시지, PR 설명(있다면), 코드에서 의도를 끌어내 명확한 문단 하나로 밝힌다. 의도가 확실하지 않으면 진행하기 전에 사용자에게 묻는다.

## 3단계, 리뷰어 띄우기

Task 도구로 모든 리뷰어를 메시지 하나에서 띄운다. `~/.cursor/rules/pstack-models.mdc`의 `interrogate reviewers` 줄 항목마다 하나씩 두고, 항목 수에 맞춰 Reviewer A, B 순으로 라벨을 붙인다. 규칙이나 그 줄이 없으면 표의 기본값을 쓴다.

| Subagent | 기본 모델 |
|----------|---------------|
| Reviewer A | `claude-opus-5-5-xhigh` |
| Reviewer B | `grok-4.7-xhigh-fast` |

리뷰어마다 `subagent_type: generalPurpose`, `readonly: true`를 주고, `model`은 설정된 항목으로, 설정된 줄이 없으면 표의 기본값으로 둔다. `auto`나 `inherit-parent` 항목이면 `model`을 생략해 그 리뷰어가 부모 모델로 돌게 한다.

Task 도구가 설정된 항목을 거부하면 그 리뷰어를 같은 계열의 표 기본값으로 돌리고 그렇다고 알린다. 계열은 접두사로 구분한다. `claude-*`가 한 계열이고, `grok-*`는 `cursor-grok-*`, `composer-*`와 한 계열이다. 거부된 `composer-*` 항목은 Reviewer B의 기본값으로 돌린다. 맞는 계열이 없으면 Reviewer A의 기본값을 쓴다. 표 기본값이 거부되면 오류 메시지의 유효한 slug 가운데 가장 가까운 대응(같은 계열과 같은 추론 등급을 선호)으로 띄우고, 기본값 표를 갱신하는 PR을 따로 연다. slug 문제로 리뷰를 막지 않는다. 별칭 항목은 절대 거부된 slug로 다루지 않고, 어느 대체 규칙도 적용하지 않는다.

`references/reviewer-prompt.md`를 읽고 모든 리뷰어에게 같은 템플릿을 밝힌 의도, diff나 파일 내용, `references/rubric.md`의 루브릭, `references/code-quality-review.md`의 코드 품질 관점으로 채워 준다. 각 subagent의 추론 수준과 속도(fast 또는 표준)는 **poteto-mode** 스킬의 Subagents 절에 따라 작업에 맞게 고른다.

## 4단계, 종합하기

결과가 돌아오는 대로 하나로 합친 그림을 만든다. 모든 리뷰어의 지적을 파싱한다. 같은 문제를 다르게 묘사한 지적은 합치고, 각각 어느 모델이 냈는지 적는다. 두 개 이상의 모델이 독립적으로 낸 지적이 가장 강한 신호다. 한 모델만 낸 지적도 읽되 그만큼 가중치를 낮춘다. 불일치를 적는다. 한 모델이 무언가를 지적하고 다른 모델이 명시적으로 반대를 말한다면, 판정에 쓸 맥락이다.

## 5단계, 리드의 판단

나는 중립적인 집계자가 아니라 리드 리뷰어이자 실용적인 시니어 엔지니어다. 전체 틀은 `references/lead-judgment.md`를 읽는다. 모든 지적을 네 분류 가운데 하나에 넣고, 낸 모델과 분류 근거 한 줄을 붙인다.

- **조치(Act on)**. 실제 목표에 비춰 정확성, 보안, 유지보수성에 영향을 주는 진짜 문제. 실제 PR이라면 막을 것들이다.
- **검토(Consider)**. 타당하지만 지금 다루는 비용보다 큰지 확신이 없다. 사용자가 주목할 만하다.
- **참고(Noted)**. 기술적으로는 맞지만 조치할 것은 아니다. 맥락에 달렸거나, 섣부른 최적화이거나, 현재 단계에서는 영향이 작다.
- **기각(Dismissed)**. 틀렸거나, 사소한 트집이거나, 맥락을 놓쳤다. 이유를 짧게 붙인다.
