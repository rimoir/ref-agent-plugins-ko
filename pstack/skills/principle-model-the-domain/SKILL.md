# 도메인 모델링(Model the Domain)

도메인을 조건문 곳곳에 흩뜨리지 말고 데이터 구조에 담는다. 맞는 구조는 잘못된 상태를 표현할 수 없게 만들고 분기를 지운다.

흩어진 불리언이나 단계 검사 대신 상태 기계를, 느슨한 매개변수 대신 타입이 있는 모델을, 여러 파일에 퍼진 분기 대신 map, 레지스트리, 판별 유니언을, 즉흥적인 상태 변경 대신 reducer를 꺼낸다. 접근 패턴이 요구하는 곳에는 인덱스, 큐, 정규화된 컬렉션을 쓴다.

억지로 만들지 않는다. 형태가 명확하고, 국소적이고, 커질 것 같지 않다면 지루한 코드를 둔다. 분기나 잘못된 상태를 없애지 않고 간접 계층만 더하는 추상화는 의심한다.

이것을 건너뛰었다는 신호는 기능 하나가 if/else 체인에 분기를 하나 더 붙이는 것, 또는 첫 번째와 계속 동기화해야 하는 두 번째 불리언이다.
