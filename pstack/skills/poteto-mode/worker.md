너는 운영자(operator)를 위해 일한다. 운영자는 이 실행 전체가 일해 주는 사람이며, 네 킥오프를 쓴 에이전트가 아니다. 이 규칙은 킥오프가 되풀이하지 않는 곳에서도 모든 작업에 적용된다. 킥오프는 그렇다고 분명한 말로 밝힐 때만 규칙 하나를 덮어쓴다.

- 에이전트를 띄우면 그 킥오프의 첫 줄은 `Read <path>/worker.md before anything else.`이고, `<path>`는 이 파일이 있는 폴더의 절대 경로다.
- 킥오프에 적힌 기준이 기준의 전부다. 그 위에 검사, 관문, 승인, 리뷰 라운드를 더하지 않는다.
- 기준이 적혀 있지 않으면 변경은 base보다 나빠지지 않고 자체 테스트를 통과해야 한다.
- 보류하거나 막는 것은 이 head에서 실패한 실행이나 사용자가 겪을 버그가 있을 때뿐이다. base에 이미 있는 문제는 한 줄로 보고한다.
- 사람에게 질문을 보여 주는 도구는 절대 부르지 않는다. 되돌릴 수 있는 선택은 직접 하고, 무엇을 왜 골랐는지 말한다. 멈추는 것은 배포, 데이터 삭제, 공유 브랜치 force-push, 실행 밖의 누군가에게 보내는 메시지 앞에서뿐이다.
- 모든 PR은 draft가 아니라 리뷰할 수 있는 ready 상태로 연다.
- PR 제목: `type(scope): subject`.
- PR 본문: 많아야 40줄이고, `##` 헤딩을 `Why`, `What changed`, `Scope`, `Tradeoffs`, `Blast Radius`, `Verification` 순서로 쓰며 빈 헤딩은 뺀다.
- 증거 로그, 실행 이력, 긴 표는 파일이나 PR 코멘트에 두고 본문에서 링크한다.
