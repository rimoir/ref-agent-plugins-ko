# 이슈 트래커: 로컬 마크다운

이 저장소의 이슈와 스펙은 `.scratch/` 아래 마크다운 파일로 관리한다.

## 사용 규칙

- 기능 하나에 디렉터리 하나: `.scratch/<feature-slug>/`
- 스펙은 `.scratch/<feature-slug>/spec.md`에 둔다.
- 구현 이슈는 티켓 하나에 파일 하나로 `.scratch/<feature-slug>/issues/<NN>-<slug>.md`에 둔다. 번호는 `01`부터 매기고, 티켓을 한 파일에 모아 두지 않는다.
- 분류 상태는 각 이슈 파일 위쪽의 `Status:` 줄에 적는다(역할 문자열은 `triage-labels.md` 참고).
- 댓글과 대화 기록은 파일 맨 아래 `## 댓글` 제목 밑에 덧붙인다.

## 스킬이 "이슈 트래커에 게시한다"고 할 때

`.scratch/<feature-slug>/` 아래에 새 파일을 만든다(필요하면 디렉터리도 만든다).

## 스킬이 "관련 티켓을 가져온다"고 할 때

참조된 경로의 파일을 읽는다. 보통 사용자가 경로나 이슈 번호를 직접 알려 준다.

## wayfinder 작업

`/wayfinder`가 쓴다. **계획 이슈**(map, 결정 목록과 하위 티켓을 묶는 상위 이슈)는 파일 하나이고, 티켓마다 **하위** 파일이 하나씩 있다.

- **계획 이슈**: `.scratch/<effort>/map.md` 파일을 쓴다. 본문에 메모 / 지금까지의 결정 / 아직 정하지 못한 것을 담는다.
- **하위 티켓**: `.scratch/<effort>/issues/NN-<slug>.md`. 번호는 `01`부터 매기고 본문에 질문을 적는다. `Type:` 줄에 티켓 유형(`research`/`prototype`/`grilling`/`task`)을, `Status:` 줄에 `claimed`/`resolved`를 적는다.
- **차단 관계**: 위쪽에 `Blocked by: NN, NN` 줄을 적는다. 여기 적힌 파일이 모두 `resolved`가 되면 티켓의 막힘이 풀린다.
- **진행 가능 목록**: `.scratch/<effort>/issues/`에서 열려 있고, 막히지 않았고, 아무도 맡지 않은 파일을 찾는다. 그중 번호가 가장 앞선 파일을 고른다.
- **맡기**: 작업을 시작하기 전에 `Status: claimed`로 바꾸고 저장한다.
- **해소**: `## 답` 제목 아래에 답을 덧붙이고 `Status: resolved`로 바꾼 다음, `map.md`에 있는 계획 이슈의 '지금까지의 결정' 섹션에 컨텍스트 포인터(요지와 링크를 담아 원래 자료를 가리키는 짧은 참조)를 덧붙인다.
