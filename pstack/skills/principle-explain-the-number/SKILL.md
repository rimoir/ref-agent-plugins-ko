# 숫자를 설명하라(Explain the Number)

- **실행 전에 결정을 적는다.** 그 결정을 바꿀 결과와 잡음 하한을 밝힌다. 실행 사이의 편차가 효과보다 크면 멈춘다.
- **"왜 두 배가 아닌가?"를 묻는다.** 결과를 묶어 두는 자원이나 코드 경로를, 실행 중에 뜬 프로파일이나 카운터에서 찾아 짚는다. 코드를 읽고 한 추측은 제한 요인이 아니다.
- **숫자가 그 밖에 무엇을 재고 있을 수 있는지 나열하고**(오류, 건너뛰었거나 캐시된 작업, 아예 돌지 않은 코드, 튜닝하지 않은 한쪽, 잡음, 의미 없을 만큼 작은 조각) 하나씩 증거로 배제한다.
- **실행 횟수, 편차, 제한 요인을 숫자 곁에 둔다.**

성능 숫자라면 [benchmark-checklist](../benchmark-checklist/SKILL.md) 스킬을 돌린다. eval 결과라면 모든 실행이 과제를 해냈는지, 차이가 시행과 모델을 넘어 유지되는지, 그 시나리오가 중요한지 묻는다.
