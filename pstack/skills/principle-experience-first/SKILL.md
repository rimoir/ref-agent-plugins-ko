# 경험 우선

구현의 편의와 사용자의 즐거움이 부딪히면 즐거움을 고른다.

- 모든 기능, 컨트롤, 옵션은 존재 이유가 있어야 한다
- 덜 출시하고 더 잘 출시한다(기능 셋으로 다듬은 경험이 기능 열로 거친 경험을 이긴다)
- 확정하기 전에 프로토타입을 만든다(설계 결정은 프로덕션 코드보다 버릴 HTML에서 더 싸다)
- 세부 사항을 제대로 잡는다(전환, 정렬, 간격, 피드백, 에러 상태)
- 핵심 루프를 조인다(모든 기능은 중심 워크플로에 봉사하거나 비켜 서야 한다)

사용자는 작업 결과를 소비하는 누구든이다. UI라면 최종 사용자다. 라이브러리나 내부 API라면 그것을 import하는 동료다. 다음에 그 코드를 유지보수할 엔지니어도 사용자다. 그들의 경험도 같은 방식으로 따지고, 영향은 그들의 관점에서 설명한다.

기초는 경험에 봉사해야 한다. 기초적 사고는 작업의 *순서*를 다스린다. 이 원칙은 *목표*를 다스린다.
