# MISSION.md 형식

`MISSION.md`는 작업 공간 루트에 둔다. 사용자가 이 주제를 배우는 _이유_를 담는다. 무엇을 다음에 가르칠지, 어떤 자료를 보여 줄지, 어떤 연습 문제를 설계할지 같은 모든 가르침의 결정은 이 문서에 근거해야 한다.

## 템플릿

```md
# 학습 목적: {주제}

## 이유
{1~3문장. 사용자가 이루려는 구체적인 실제 목표. 이 기술을 갖추면 사용자의 생활이나 일에서 무엇이 달라지는가? "X를 이해하기 위해" 같은 추상적인 표현은 피하고, 그 밑에 있는 실제 결과를 끌어낸다.}

## 성공 기준
- {사용자가 할 수 있게 될, 구체적이고 겉으로 확인할 수 있는 일}
- {또 다른 구체적인 일}
- {…}

## 제약 조건
- {시간, 예산, 이미 정해진 일정, 학습 선호 등 접근 방식을 제한하는 모든 것}

## 범위 밖
- {사용자가 지금은 명시적으로 다루고 싶지 않다고 한 인접 주제. 근접 발달 영역을 지키기 위해 적는다}
```

## 규칙

- **작업 공간 하나에는 학습 목적을 하나만 둔다.** 사용자가 서로 관련 없는 두 가지를 배우고 싶어 하면 작업 공간을 둘로 나눈다.
- **추상적인 것보다 구체적인 것을 쓴다.** "몸을 더 건강하게"보다 "10월까지 하프 마라톤 완주"가 낫다. "Rust 배우기"보다 "팀에 Rust CLI 배포하기"가 낫다.
- **모호하면 되묻는다.** 사용자가 이유를 설명하지 못하면 무엇이든 쓰기 전에 사용자를 인터뷰한다. 나쁜 학습 목적은 학습 목적이 없는 것보다 나쁘다.
- **상황이 바뀌면 고친다.** 학습 목적은 바뀐다. 사용자의 목표가 달라지면 이 파일을 고친다. 낡은 학습 목적이 다음 세션의 방향을 정하게 두지 마라.
- **짧게 쓴다.** `MISSION.md`가 한 화면을 넘어가면 방향을 알려 주는 문서가 아니라 세부 계획서가 된 것이다.
