# 검증 절차와 과거 비교의 한계

## 과거 비교 실험의 현황

v2 설계는 메인테이너가 직접 진행한 탐색적 비교를 참고했다. 이 비교는 이전 버전 README에 다음과 같이 설명되어 있다.

- 구축 작업 두 개
- 작업마다 스킬 없음, tree 3, tree 6 조건
- 조건마다 새 폴더와 새 세션 하나씩
- 독립 검토, 적대적 검증, 브라우저 테스트

이전 문서는 출력 토큰 비율, 에이전트가 스스로 찾은 결함 수, 실제 동작 중에 드러난 실패 한 건, 보고서의 숫자 오류를 보고했다. 이 저장소에는 그 6회 실행의 정확한 프롬프트, 모델과 하네스 버전, 실행 기록, 토큰 로그, 출력 저장소, 검토자 양식, 브라우저 녹화, 계산 코드가 없다. 따라서 보고된 숫자는 원자료로 독립적으로 재현하거나 점검할 수 없다.

과거 비교는 설계가 어디서 나왔는지 보여 주는 기록으로만 다룬다. 모델 전반에 관한 주장을 하기에는 규모가 너무 작고, unlazy가 특정한 개선이나 비용 배수를 일으킨다는 증거로 설명해서는 안 된다.

## 재현 가능한 재실행을 위한 최소 절차

### 1. 비교 조건 사전 등록하기

실행 전에 다음을 기록한다.

- 정확한 unlazy 커밋과 조건 정의
- 작업 프롬프트와 공유 입력 자료
- 에이전트 제품, 모델 id, 공개된 경우 모델 스냅샷, 추론 설정, 권한
- 운영체제, 런타임 버전, 브라우저, 패키지 관리자, 네트워크 정책
- 타임아웃, 재시도, 실패 처리 규칙
- 지표, 채점 기준표, 검토자 지침, 제외 기준
- 무작위로 정한 실행 순서와 계획한 독립 반복 횟수

작업과 조건의 조합마다 두 번 이상 실행한다. 조합마다 한 번만 실행하면 조건의 효과와 실행마다 생기는 편차를 구분할 수 없다.

### 2. 실행마다 환경 분리하기

실행마다 새 세션과 새 작업 사본을 쓴다. 시험하는 개입만 빼고 모든 조건에 같은 작업 본문, 도구 접근 권한, 시간 제한, 환경을 준다. 한 실행의 결과물이나 검토자 메모가 다른 실행에 보이게 하지 마라.

다음을 보관한다.

- 정확한 첫 프롬프트와 모든 후속 메시지
- 에이전트와 도구의 전체 실행 기록
- 시작 시점과 종료 시점의 저장소 커밋
- 의존성 매니페스트와 lockfile
- 테스트, 린트, 빌드, 브라우저 로그
- 채점 기준표가 요구하는 스크린숏이나 녹화
- 하네스가 내보낸 그대로의 토큰 데이터와 시간 데이터

결과와 관련된 내용은 바꾸지 않은 채 자격 증명을 가린다. 모든 보관 자료의 체크섬을 공개한다.

### 3. 지표를 조작적으로 정의하기

측정한 대리 지표와 연결하지 않았다면 "노력"("effort") 같은 이름표를 쓰지 않는다. 다른 검토자가 보관 자료로 계산할 수 있도록 지표마다 정의를 적는다.

다음 지표를 권한다.

- 요청된 완료 판정 결과 중 최종 답변 전에 충족한 것
- 고정된 검색 규칙으로 찾은 플레이스홀더나 연기된 작업의 출현 횟수
- 테스트, 빌드, 콘솔, 브라우저 실패
- 중복 결함 판정 규칙을 적용해 센, 전달 전에 찾아서 고친 결함
- 최종 보고에 들어간 거짓 완료 주장
- 스크립트로 측정한 값과 비교해 틀린 숫자 주장
- 같은 하네스가 보고한 입력 토큰, 캐시된 입력 토큰, 출력 토큰
- 재시도를 포함한 실제 경과 시간

체크포인트 성공과 엔드투엔드 작업 완료를 구분한다.

### 4. 블라인드 검토와 중복 검토

가능하면 검토 자료에서 조건 이름표를 지운다. 주관적 기준에는 독립 검토자를 두 명 이상 둔다. 의견 불일치와 해결 규칙을 기록한다. 검토자에게 기대하는 결과 방향을 알려 주지 마라.

객관적 검사는 보관 자료에 고정해 둔 스크립트로 실행한다. 무언가가 없다는 주장(negative assertion)에는 양성 대조(검사가 반드시 걸러 내야 하는 알려진 입력)를 넣어, 그 주장이 실제로 실패할 수 있음을 보인다.

### 5. 계산 과정 공개하기

실행마다 기계가 읽을 수 있는 행 하나와, 모든 표와 차트를 다시 만들어 내는 스크립트를 제공한다. 비율과 함께 원시 개수, 불확실성, 제외 항목, 누락 데이터를 보고한다. 탐색적 발견은 사전 등록한 결과와 분리한다.

### 6. 결론의 범위 제한하기

결과는 시험한 모델, 스냅샷, 작업, 환경에 한정해 서술한다. 작은 코딩 비교 결과를 모든 에이전트나 모든 큰 작업으로 일반화하지 마라. 실패와 효과가 없다는 결과도 개선만큼 신중하게 기록한다.

## 저장소 수준 검증

현재 구현에는 파서, 검사기, 점유(lease), 훅, 설치 스크립트, 이식성 동작을 확인하는 별도의 결정적 테스트 모음이 있다. 저장소 문서에 적힌 테스트 명령으로 실행한다. 이 소프트웨어 테스트는 구현 동작을 검증한다. 모델 심리나 작업 생산성에 관한 폭넓은 주장은 검증하지 않는다.
